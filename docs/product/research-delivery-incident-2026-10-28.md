# 研究交付与请求限流故障（2026-10-28）

## 现场结论

对 `10.7.0.18` 的只读排查确认，受影响研究为 v1–v6，共五次计划修订；12 个当前任务均为 completed，决策记录中没有 G4。这是交付申请校验失败，非确认弹窗丢失。DAG 节点展示专家任务状态，不代表研究包交付已获确认。

该研究有 9 条 experiment 声明，其登记日志 SHA-256 全部与当前日志一致；另外 2 条 inference 声明引用相同 Run，但按证据登记合同不保存实验摘录或日志哈希。`research_package_scope` 过去对所有带 runId 的声明比较日志哈希，将推断声明的 None 误判为日志变化。修订计划不会改变这两条声明，因此无法解除阻塞。其他声明和 Run 来源继续保留，不通过改写或删除历史数据解锁交付。

界面过去只要任务全部 completed，且没有批准的交付决策，就显示“等待结果确认”，没有区分“已申请、待用户确认”与“校验失败、申请尚未生成”。人工确认原本位于专家团面板的“人工确认”页；仅有 completed 节点时无法推出存在待确认项。

网关最近 24 小时记录 2,618 次 HTTP 429，其中 2,308 次是 `/api/projects/activity`、111 次是会话列表请求。聊天 full/delta 事件都会触发活动汇总失效，原前端仅合并 100 毫秒内的事件；连续输出、多专家和多窗口会持续读取活动汇总。活动、会话与研究 API 共用每用户/空间 600 次/分钟的额度，导致汇总刷新阻断会话列表和科研状态读取。并非模型供应商配额错误。

## 实施

- `src/store/research.rs` 仅对 experiment 声明校验登记日志哈希；推断保留类型和 Run 关联，不提升为实验依据。Run 来源、产物完整性、审稿证据摘要及真实实验日志变化仍需通过交付校验。
- 后台巡检保存 `deliveryError`，成功校验及新计划清除该错误；无待确认项时显示“交付确认尚未生成”，实际阻塞原因在人工确认页展示。
- 项目活动刷新按 5 秒合并，会话侧栏事件刷新按 1 秒合并；连续事件不会无限推迟最终刷新，工作空间切换/组件卸载取消旧定时器。
- 平台将活动汇总、一般读取、写入分成独立限流桶。活动桶每分钟 120 次，读取和写入分别保留每分钟 600 次；旧客户端的活动请求也不会耗尽人工决策或会话导航额度。
