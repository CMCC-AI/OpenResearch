# 精选案例：真实项目的公开研究档案

精选案例展示已经执行过的项目。点击卡片进入原生项目工作区的只读模式，不再填入研究目标，也不自动创建项目或执行模型调用。

## 管理与发布

只有账号平台的系统管理员（`platform_users.is_admin=true`）可以管理案例。科研空间 owner 与系统管理员为两个独立权限；owner 不会自动提权。管理员也不会因此获得其他用户原项目的访问权限。

管理员从“系统管理 → 精选案例管理”（`/admin/cases`）选择自己有权访问的项目，点击“加入案例集”。项目名称作为案例标题，主会话标题作为简介；系统完整复制原项目并直接发布给所有登录用户。首页“管理精选案例”和项目菜单“添加到精选案例”也进入此页面，项目快捷入口会预先选中该项目。旧 `/cases/manage` 地址继续跳转并保留有效的项目参数。

加入操作会复制这个项目在 orx 中保存的全部研究会话，包括归档会话、分支消息、工具输入/输出、提示和嵌套智能体记录。运行中的研究、排队消息或读取期间变更的会话会阻止复制；复制中断后可从管理页继续加入。

项目使用的文件复制为独立字节副本，记录大小与 SHA-256。添加后所有登录用户都能查看项目完整历史和文件；加入前应确认项目内容适合公开。原项目权限不会改变。移出案例集会立即下架副本，不影响原项目。

会话中引用的注册材料包同时保存 `/api/materials/<材料ID>` 清单和每个原文件的下载映射。材料必须属于当前项目并被已保存会话引用；文件下载只允许清单内的来源标识，且副本名中的 SHA-256 必须与材料记录一致，缺失文件不能发布。原路径、来源标识、格式与阅读状态原样保留，材料复制不代表其内容已被阅读。

未完成文件上传的案例不能加入案例集。发布要求草稿版本号保持一致；需要更新案例时先移出，再从原项目重新加入。下架操作也校验版本。

## 普通用户

普通账号登录后可以打开 `/cases`（现有服务器子路径为 `/mobilesci/cases`），查看已发布案例及 `/cases/<案例ID>` 的完整对话、时间顺序、分支关系和成果文件。无共享科研空间权限的账号从科研首页转到案例页，导航中不加载私有项目、事件流、研究偏好或远程主机配置。

公共读接口验证有效登录会话。草稿与下架案例返回 404，普通账号不能调用管理接口。原项目仍通过既有空间授权与网关鉴权访问；新建的 `catalog-session` 只供案例与页面权限判断，原 `browser-session` 的共享空间 owner 检查保留。

案例直接挂载实际项目页面 `App` 与原有 `ChatPanel`，不另建对话渲染器、文件列表或专家团页面。原页面使用的项目元数据、会话与消息（包含原始 parts、分支和完成时间）、工作区标签布局、文件树、文件内容、研究状态、实验、日志和变更记录按原生 API 响应保存。原有文件预览、专家团 DAG、工作过程折叠、子智能体和实验详情都由同一套组件读取这些副本。输入区保留原来样式并禁用输入；写操作、执行、新建会话和文件编辑不可用。

`ReadOnlyProject` 为原页面安装独立的案例数据源与查询作用域，不改写全局 fetch，也不会把读取缺失资源的请求退回原项目。布局调整与分支切换只改变当前读者的内存状态；其余写 API 返回 403。进入案例时停止私有项目的事件订阅。文件 URL 只能映射到已复制的案例附件；未复制的路径返回 404，不读取发布者机器上的其他文件。

加入案例会完整复制原项目工作区和成果目录中的文件（以原页面的文件树为准），对重复内容按 SHA-256 合并存储；研究状态、确认记录及运行日志通过原生 API 响应保存。读取期间会话变化、运行中的会话或实验、排队消息、被截断的文件列表、超限文件都会拒绝加入，不能省略文件。

旧版文本快照不再伪装成原项目页面。管理员可从原关联项目同步完整工作区，或生成新草稿。来源已删除或无访问权限时不能补造数据。管理员可以通过 `/cases/<案例ID>?preview=1` 打开草稿的完整项目页面预览；普通用户仍只能读取已发布案例。

为了让原页面正常解析已有的文件引用，完整副本保留该项目原始 ID、会话 ID 和目录元数据；这些值不赋予访问原项目的权限，案例读取只在已复制的数据与文件内完成。补充成果通过专用 ID 以附件下载；原生文件预览通过案例 assets 接口按文件类型返回，并支持 HEAD 和范围读取。文件响应设置 sandbox CSP 和禁止缓存，文件查看器沿用原项目的预览方式。下架后新的详情和文件请求都被拒绝；页面每 30 秒重新检查可用性。已经下载或已经被用户保存的内容不能撤回。

## 存储和接口

原始项目、对话和成果仍留在原 orx；管理员生成的案例副本进入账号平台 PostgreSQL，只有已发布状态对普通用户可见。追加迁移 `005.sql` 创建 `featured_cases` 与 `featured_case_files`，不修改已有用户、项目或密码。发布者账号信息不会写入副本；完整工作区中的原项目标识和路径只用于恢复原页面引用，账号凭据不属于采集范围。

- `GET /api/platform/cases`：已发布案例列表。
- `GET /api/platform/cases/:id`：完整公开快照及成果清单。
- `GET /api/platform/cases/:id/files/:fileId`：成果字节副本。
- `/api/platform/admin/cases`：系统管理员创建和列举草稿。
- `/api/platform/admin/cases/:id`：管理员预览；DELETE 只删除草稿及其副本。
- `/api/platform/admin/cases/:id/files`：为草稿上传成果副本。
- `GET/HEAD /api/platform/cases/:id/assets?name=...`：原生页面文件预览，支持范围读取并按发布状态鉴权。
- `POST /api/platform/admin/cases/:id/native`：按版本同步原关联项目的完整副本与文件。
- `/api/platform/admin/cases/:id/{publish,unpublish,order}`：审核发布、下架、排序。

跨源调用仅允许已配置的账号/科研页面 origin 和有效工作空间 origin；写操作校验来源，上传完成后重新验证管理员身份。管理写操作记录审计事件，审计不记录对话、文件内容或账号凭据。

完整项目副本的元数据上限为 16 MB，项目文件单个上限 128 MB、最多 2,000 个、去重后总量 512 MB；迁移 `008.sql` 将数据库约束同步到这些上限。额外补充成果继续按单个 25 MB、总量 200 MB 限制。旧版文本快照限制为单条消息文本及结构化片段各 2 MB、最多 500 个会话及 50,000 条消息。超过限制会拒绝加入，不截断研究过程。案例列表最多返回 200 项。

## 验证与部署

案例文件哈希在 HTTPS 环境优先使用 Web Crypto；公网 HTTP 环境缺少 `crypto.subtle` 时使用 JavaScript SHA-256 实现，文件命名、去重及服务端校验保持一致。升级此兼容修复需要重新构建前端并更新承载内嵌 `ui/dist` 的服务器二进制与执行器镜像，包括现有私人空间及后续新建空间使用的镜像。还须检查账号平台的独立静态目录和 Nginx 实际挂载的发布目录；Nginx 直供静态文件时，更新镜像不会更新其宿主目录。先同步新资源，再原子替换入口 HTML，并从对外 URL 核验入口引用及 JS 字节哈希。无需数据库迁移。升级后刷新浏览器，选择包含文件的项目验证加入案例集。

数据库集成测试覆盖普通用户与 owner 不得发布、登录/来源校验、草稿隐藏、上传完整性与版本冲突、发布后的完整对话及附件响应、禁止修改已发布快照、下架撤销读取、管理员权限即时撤销和会话退出。前端测试覆盖真实案例路由、归档/分支保留、运行中与变化中源项目拒绝导入、超大文件流取消，以及结构化快照保真、工具/子智能体展开内容、原生 Markdown 排版与对话 HTML/私有文件引用不执行。

部署前须应用账号迁移、更新账号平台代码，并随 Rust 二进制更新已重新生成的 `ui/dist`。不需要新增服务器 env 字段。公开副本随账号 PostgreSQL 备份一起保存；旧原项目数据和原文件不因案例下架或删除而改变。本轮实现不自动分配线上管理员角色，也不自动选择或发布线上项目。

## 统一系统管理入口

`/admin/users` 与 `/admin/cases` 共用系统管理布局和导航，管理员从账号平台登录后默认进入用户管理。现有 MobileSci 部署对应 `/mobilesci/admin/users` 和 `/mobilesci/admin/cases`；原 `/_account/login?admin=1` 入口继续有效，登录后转入统一后台。

后台导航不加载私人项目列表。用户管理沿用账号平台现有只读元数据接口，支持姓名/邮箱搜索与分页，不增加用户研究内容访问权限。普通用户不能挂载后台内容，管理 API 继续检查当前管理员身份。跨 origin 的本地 Web 只允许明确配置的应用 origin；私人空间访问管理 API 时仍先验证空间归属。

## 原项目不可用时的历史案例

案例是独立保存的副本。原项目删除或当前工作空间找不到源项目时，保留已发布案例和预览入口，并显示来源不可用提示；项目列表加载中或请求失败时不据此判断源项目状态。

草稿支持“发布已保存副本”：管理员先查看副本并确认审核，再按当前版本发布，不依赖原项目或科研运行环境。后端继续校验版本和文件完整性，缺失文件不能发布。仍能访问原项目时，可选择“从原项目更新并加入”重新复制最新内容。

不需要的历史草稿可在明确确认后删除，删除范围仅含案例草稿及其文件副本。已发布案例须先移出案例集再删除；不自动清理、下架或发布历史记录，也不改变原项目数据。
