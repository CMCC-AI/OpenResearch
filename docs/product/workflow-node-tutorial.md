# 研究工作流节点使用教程

面向在画布上编排研究流程的主理人。每个节点讲清楚：它解决什么问题、怎么添加、怎么配置、运行时会发生什么。规则描述与代码校验一致（`ui/src/workflow/model.ts`，2026-11-19）。

## 一、专家任务：让某位专家干一项活

**什么时候用**：绝大多数节点都是它。你要表达的是「谁、做什么、交出什么文件」。

**怎么加**：把专家从专家库拖进画布。默认简报是「请完成"XX"承担的科研任务，并记录使用的方法、证据和限制」，默认产物是 `task-N/result.md`，都可以改。

**配置项**：

| 配置 | 说明 |
| --- | --- |
| 任务简报 | 给专家的开工指令，写清要做什么、注意什么。 |
| 产物路径 | 专家把结果写进研究目录的哪些文件（相对路径，不能以 `/` 开头或含 `..`）。下游节点靠这些文件接力。 |
| 输入产物 | 勾选直接前置任务的产物；任务开始时会自动带上这些文件，注入专家的开工指令。 |
| 汇合方式 | 有多条前置线时，缺省「等全部完成」；选「任一前置完成即继续」则任意一条完成就放行（需要至少两条前置连线）。 |
| 完成后需主理人确认 | 开启后任务完成先暂停，你批准后下游才开始。运行视图会生成对应的「任务检查点」。 |
| 结论把关：有问题时暂停下游 | 开启后专家完成时要给出结论（通过 / 有问题）；有问题时下游暂停并通知你。 |
| 结论有问题时自动返工 | 配合结论把关使用：带问题说明自动重跑相关任务，每轮单独记录，上限 0–3 轮，会写进你确认的计划。 |

**返工 vs 分流怎么选**：想让系统自动修正，用「自动返工」；想走备用路径（比如降级方案），用「条件分流」节点。

## 二、条件分流：运行时二选一

**什么时候用**：上游做完后要走两条路——比如「审查通过就写综述，有问题就先补检索」。运行到这一步自动判定，只放行其中一条分支，另一条显示「已跳过」。

**怎么加**：从节点库拖入「条件分流」，从上游连一条线进来，再向下连出两条线：第一条自动标「成立」，第二条标「不成立」，可在属性面板改。

**配置项**：

| 配置 | 说明 |
| --- | --- |
| 判断条件 · 结论 | 读取某个前置任务完成时的结论，等于「通过」或「有问题」时走「成立」分支。条件来源必须是**直接前置任务**中**已开启结论把关**的那个产物。 |
| 判断条件 · 上游失败 | 前置任务失败时走「成立」分支，用于兜底路径；不需要选来源产物。 |

**规则**：分流节点不选专家、不产出文件；两条分支都必须有后续任务（「不成立」是默认出口，不能省）；它本身不支持确认、把关、返工。

---

## 三、逐项处理：把一份清单逐条跑完

**什么时候用**：上游产出一批同类东西（比如 20 篇入选论文），要对每一项做同样的处理（逐篇精读），而不是派一个专家一次性读完全部。

**怎么加**：从节点库拖入「逐项处理」，从产出清单的上游连一条线进来。

**配置项**：

| 配置 | 说明 |
| --- | --- |
| 列表来源 | 直接前置任务的产物，且它旁边要有 `.items.json` 清单（如 `discovery/papers.md` 配 `discovery/papers.md.items.json`）。给上游专家的简报里写明「同时输出清单文件」，派发时系统也会提醒它写。清单在首次派发前固化，执行期间不再重读。 |
| 产物模板 | 必须含 `{item}` 占位，如 `readings/{item}.md`，每项各生成一个文件。 |
| 逐项简报 | 每项派给专家的话，`{item}` 会替换成该项标题。 |
| 失败策略 | 某一项失败时：缺省「暂停等待主理人」；选「跳过」则跳过该项继续剩余项。 |

**规则**：逐项执行（一批一项接一项）；不选专家、不直接声明产物（产物由模板按项展开）；不支持完成后确认、结论把关、返工。

---

## 四、人工任务：等你完成的一项

**什么时候用**：某个环节必须你亲自来——挑定最终方案、定标题、拍板纳入标准。

**怎么加**：从节点库拖入「等你完成的一项」，连好前后顺序。

**怎么配**：只需要名称说明和一个产物路径（你的提交会写进这个文件，路径必须恰好一个）。

**运行时**：前置完成后，这项任务在研究面板显示「等你完成」：把你的产出以文字提交，写入文件后流程自动继续。提交本身就是验收，所以它不再叠加「完成后确认」，也不支持把关、返工、分流等配置。

AI 不会代写或代提交这一步。如果产物文件在验收后被外部改写，原验收会作废，任务回到「等你完成」；重新提交后才继续。已完成的人工任务可以在任务卡点「修改这一步」撤回重提，下游任务会一起回到待执行；交付确认后的修改需走计划修订（forceRerun）。

---

## 五、实验节点：批准后自动跑实验

**什么时候用**：流程中要真正执行一次实验运行（训练、评测、批量计算），而不是让专家写文档。

**怎么加**：从节点库拖入「实验节点」，连好前置。实验运行的契约（在哪个后端跑、用什么参数）通过现有研究运行流程绑定。

**怎么配**：名称说明 + 声明产物（1–30 个相对路径，每行一个）。运行结束后就按这些文件验收——成功但产物缺失或为空，按失败处理并说明缺口。

**运行时**：没有专家会话。前置完成、运行契约获批准（G2/G3）后，引擎自动提交运行；运行全部结束、产物验收通过才放行下游。中途失败可以用重试移除运行归档后重跑。它不需要「完成后确认」——批准契约就是授权。

---

## 六、事件等待：等一个文件出现

**什么时候用**：流程要停下来等外部结果落盘——比如等服务器上的评测脚本写出结果文件，再让后续专家接手分析。

**怎么加**：从节点库拖入「事件等待」。

**怎么配**：

- **等待出现的文件**：研究目录内的相对路径。
- **超时**：0–1440 分钟，0 表示不限时；默认 240 分钟。

**运行时**：前置完成后开始等待，路径出现即通过。超时不是静默跳过：任务转失败并通知你处理。等待节点不产出文件，不支持确认、把关、返工。

---

## 七、阶段分组：只是画布上的框

节点多时，用「添加阶段分组」按钮放一个框，把节点圈成「检索阶段」「精读阶段」等。它只帮忙看，不进入执行计划、不影响任何确认。上限 12 个，名称 1–60 字。

---

## 八、系统环节：提交后自动出现，不用手搭

这些不需要你在画布上连线，提交运行后按流程自动展示：

| 环节 | 什么时候出现 |
| --- | --- |
| 范围确认（G1） | 提交工作流后先请你确认研究范围，你批准后专家才开始工作。 |
| 任务检查点（G5） | 给专家任务开了「完成后需主理人确认」时，对应生成一个检查点。 |
| 交付确认（G4） | 全部任务完成后的成果验收。 |
| 研究交付 | 确认后的最终成果包，从聊天与运行视图进入。 |

节点库里的系统环节可以拖入画布查看说明，也可以删除；空白画布不会自动铺上它们。

## 常见保存报错速查

| 报错关键词 | 原因与做法 |
| --- | --- |
| 「还没有前置任务」 | 分流、逐项、把关都需要先从上游连线进来。 |
| 「条件来源必须来自直接前置任务的产物」 / 「未开启结论把关」 | 分流只能读直接前置中开了结论把关的产物；回到上游任务把「结论把关」打开。 |
| 「需要『成立』和『不成立』两条分支都有后续任务」 | 从分流节点连出两条线，各接至少一个任务。 |
| 「产物模板必须包含 {item} 占位」 | 逐项产物路径里写上 `{item}`，如 `readings/{item}.md`。 |
| 「产物路径重复」 / 「路径无效」 | 产物路径全工作流唯一；不能用 `/` 开头、`..`、`\` 或 `:`。 |
| 「设置了返工上限，需要同时开启结论把关」 | 返工依赖结论判定，先把「结论把关」打开。 |
| 「汇合策略『任一完成』需要至少两条前置连线」 | 「任一前置完成即继续」只在有多条前置线时才有意义。 |
| 「等待路径越界」 / 「超时需为 0–1440 分钟」 | 等待路径写研究目录内相对路径；超时按分钟填。 |
| 「最多包含 40 个任务」 | 拆成多个工作流，或把同环节合并。 |

## 串一个完整例子

「文献精读 + 审查 + 定稿」流程，把六种节点都用上：

1. **专家任务**（检索策略）：产出 `strategy/search.md`，开「完成后需主理人确认」——检索标准你拍板后再往下跑。
2. **专家任务**（文献发现）：读取检索策略，产出 `discovery/papers.md`，并让它在产物旁写出 `discovery/papers.md.items.json` 清单。
3. **逐项处理**：列表来源 `discovery/papers.md`，产物模板 `readings/{item}.md`，失败策略「跳过」——逐篇精读。
4. **专家任务**（证据审查）：读取各篇精读记录，产出 `review/verdict.md`，开「结论把关」+「最多 2 轮自动返工」——审查发现问题时自动带意见返工。
5. **条件分流**：条件「结论 = 通过」，来源 `review/verdict.md`；成立 → 综述写作；不成立 → 接一个补充检索的专家任务（备用路径）。
6. **实验节点**：跑一次批量复现实验，声明产物 `exp/metrics.md`。
7. **事件等待**：等外部服务写出 `external/eval-result.json`，超时 120 分钟。
8. **人工任务**（标题定稿）：最后由你定稿，提交即验收，随后进入交付确认。

同一张画布上，专家干活、你把关、系统自动分流和等待——这就是工作流编排的全部构件。

## AI 排流程会怎么排

「AI 排流程」生成的不再只是一串专家任务。它会按请求判断是否需要三类控制节点：

- **逐项处理**：上游产出一份 5–20 项的清单、每项要做同样的活（逐篇精读）时，生成逐项节点，而不是让一个专家一次读完。
- **人工任务**：某个只有你能做的决定（复现哪几篇、选哪个方案）会改变后面全部工作时，在那个昂贵步骤**之前**停下来等你。
- **条件分流**：某一步可能失败、而失败本身也有汇报价值时，给出「通过 / 有问题」两条路径，并让后续任务读两条分支的产出。

生成后系统会补齐下面这些机械契约，不依赖模型自觉：

| 自动补齐 | 说明 |
| --- | --- |
| 输入绑定 | 每个专家任务自动把直接前置的产物登记为输入，派发时注入并核对哈希。被分流跳过的分支输入会标注「本次未产出，可忽略」。 |
| 分流把关 | 分流节点的结论来源任务自动开启「结论把关」；分支任务自动连回该前置，保证读得到运行结果。 |
| 审查关卡 | 独立审稿自动开「结论把关 + 最多 2 轮自动返工」，引用审计自动开「结论把关」——与内置文献综述模板一致。 |
| 清单与模板 | 逐项节点的清单来源、产物模板、逐项简报缺省补齐；分支标记缺一个时按另一侧补齐。 |

仍然留给手改的：**实验节点**（需要先绑定运行契约和 G2/G3 授权）、**事件等待**、**阶段分组**。生成稿里不会出现这三类；需要时在画布上手动添加。生成完成后先过一遍画布，确认人工拍板和分流放在了你希望的位置，再提交。
