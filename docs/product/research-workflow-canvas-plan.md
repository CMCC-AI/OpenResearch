## 目标

用户在项目里打开一份系统文献综述（W1）模板，拖动专家节点，编辑任务简报与依赖，保存草稿。用户提交计划并确认研究范围后，在原专家团面板查看任务状态、来源证据和交付确认。首轮演示使用已上传、可提取文本的样例 PDF，精读页面的公网连通性单独验收。

- 前端已安装 `@xyflow/react`。专家团画布已有节点外观、主题、缩放定位、任务详情和证据入口。当前视图禁用拖动与连线。编辑器可复用节点的视觉与布局逻辑，独立管理可编辑草稿。[专家团 DAG](../../ui/src/components/ResearchTeamDag.tsx#L34)
- W1 的必需角色、依赖、输出阶段及实验限制已有前后端共享定义。用真实 W1 骨架初始化编辑器，示意图可只突出论文证据、综合和审稿等节点。[预设定义](../../ui/src/researchWorkflows.json#L2)
- Rust `PlanInput` 接收 `workflow`、`summary` 和任务列表。`TaskSpec` 接收 `id`、`role`、`brief`、`dependsOn`、`outputs` 等字段，服务端校验无环、角色、产物路径和预设约束。现有 CLI 可登记计划，现有浏览器 API 可读进度及确认审批。[计划模型与校验](../../src/store/research.rs#L32) · [CLI 计划登记](../../src/commands/research.rs#L94) · [研究 API](../../src/commands/up/research.rs#L35)

## 实施顺序

1. **可编辑原型。** 在隔离开发入口放置节点库、中央画布、右侧属性栏。首屏从 W1 模板装载专家任务。支持新增和移动专家节点、连线、删除、填写简报和声明产物。开始、G1 确认和 G4 交付显示为系统节点。连线只描述前置依赖，任务通过现有材料与产物引用读取输入。保存项目内草稿，恢复时保留位置与内容；草稿页提供结构化校验反馈。首个 PR 可以止于此处，单独评审交互和数据约定。
2. **接入实际研究。** 将任务连线转换为目标任务的 `dependsOn`，布局与视口存为草稿界面信息。为用户提交计划提供受项目、会话和当前版本约束的后端入口，使用 `research_set_plan` 登记新版本，并防止重复点击登记两次。无效草稿可保留，提交时按现有 W1 规则拒绝并定位到对应节点。登记后进入既有人工确认界面，由 G1 控制派发。先在隔离 slot 跑通，再用相同契约验证 `/mobilesci` 子路径与私人工作空间隔离。
3. **显示任务结果。** 用现有研究 API 将任务状态映射回节点，点击打开专家子会话、产物或证据。可看到失败原因和被阻塞的下游任务，由主理人通过现有研究命令重试或修订计划。G4 确认后可下载对应版本的研究包。通用变量端口、条件分支、循环、HTTP／代码节点和 Dify DSL 导入留待后续评估。

## 验收

| 场景 | 通过条件 |
| --- | --- |
| 编辑与恢复 | 从 W1 新建草稿，改节点位置、简报和一条合法依赖，保存后刷新，恢复相同草稿。 |
| 校验 | 尝试建立环、遗漏必需角色或设置越界产物路径，提交失败并指向相关节点或连线；直接调用后端也被拒绝。 |
| 确认与去重 | 连点提交只登记一个计划版本。G1 前无专家派发，批准后只启动已就绪任务；新版计划需重新确认。 |
| 真实交付 | 使用两篇已上传的可读 PDF 跑通 W1，界面可打开专家子会话和带原文定位的证据，G4 后下载对应研究包。W1 的实验运行数为零。 |
| 回归 | 普通对话及原专家团入口可用，宽屏与窄屏可操作，私人空间之间不可访问彼此草稿或计划；UI 改动包含重新构建的 `ui/dist` 并按 CI 工作流验证。 |

交互参考见 [Dify Workflow Studio](https://www.dify.ai/workflows) 和 [React Flow 的保存与恢复示例](https://reactflow.dev/examples/interaction/save-and-restore)。
