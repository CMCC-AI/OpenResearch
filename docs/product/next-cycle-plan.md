# M7 之后的需求入口

本计划只定义下一轮的准入与顺序，不承诺尚无需求依据的功能。先完成[多用户稳定版 M7](release-v0.2.23-mobilesci.7-delivery.md)，再冻结下一版范围和版本号。

## 启动条件

M7 五步交付全部通过：同候选完整 CI 和正式源码发行、真实数据副本升级回退、生产统一部署，以及新注册用户首次进入科研空间。部署记录、校验清单、回滚依据与分支清理记录齐备后，才接收下一轮功能实施。

## 下一轮优先顺序

| 顺序 | 工作 | 进入实施的依据 | 范围边界 |
| --- | --- | --- | --- |
| P0 | 已复现的登录、首次启动、额度和会话恢复故障 | 明确用户、错误或复现步骤，能定义回归验收 | 作为稳定版修补，不顺带改架构 |
| P1 | 额度预占体验、待确认用量处置 | 真实使用中出现阻塞，核清请求和账期 | 先解释与最小流程改进；计量保护保持，不随意调小模型上限 |
| P1 | 单服务器容量与冷启动体验 | 观察到排队、内存或恢复耗时问题 | 围绕已有按需运行和共享镜像，先测量，不自动拆分更多服务 |
| P2 | 官方后续回移 | 当前本地实现受影响且可复现，或已有用户使用对应后端 | 每版固定比较；未采用不视为欠债，不按提交数追齐 |
| 按需求立项 | ACP、固定数据复跑、完整环境封存、跨 Run 比较、桌面安装包 | 明确使用者、任务场景与维护责任 | 独立设计和验收，不混入普通技术债清理；PR #17 继续草稿 |

每项需求提交四个要点：解决谁的现有问题、复现或使用证据、最小交付改动、长期维护成本。未明确的项保留待评估，不先扩展实现。官方版本号与本项目产品版本分别记录，不因官方升版自动变更本地功能范围。
