## 二、下一步工作计划（分三阶段推进）

### 阶段 A：Gate 1 — `0.2.24-mobilesci.1` 本地全链路验收与正式发版上线（近期优先）

1. **恢复本地容器环境并完成端到端交互验收**
   - 修复/重启本机 Docker Desktop，分别验证 `slot-1`（`5201`/`4901` + `5300` 平台联动）与新增一键多用户模式 `./start-hosted-local.command`（`5400` 独立 Compose、`--with-quotas`、`grant-admin`）。
   - 重点覆盖新增核心路径：管理员供应商连接/在线模型探测/模型开关保存、按主对话发布案例与慢速下载、只读案例缺失 `/file` 回退产物预览、Markdown 外链图片转链接、材料阅读与引用定位。
2. **执行跨平台发行门禁与打标发布**
   - 确认发布候选提交后，遵循 `MobileSci source release` 工作流从 `release/mobilesci-0.2.24-mobilesci.1` 触发完整 CI（Linux/macOS/Windows 源码归档哈希一致、Rust 全平台、`ui` 审计与构建、`executor-tools` 离线自检、`platform` PG 集成、macOS/Linux Poppler 真实 PDF）。
   - CI 全绿后创建不可变 Git 标签与 GitHub Release，核对 4 个正式附件摘要并归档发行回执。
3. **生产受控升级切换（`ssh root@10.7.0.18`）**
   - 沿用[运行与部署约定](runtime-and-deployment.md)与 M7 门禁：升级前先完成 PostgreSQL、各用户 SQLite、配置与现有容器备份及实时空闲门禁检查。
   - 重新构建平台与执行器镜像（同步 `/opt/opencode-npm-cache` 与最新 `orx`、`ui/dist`），同步更新平台、provisioner、存量私人执行器及持久化 Compose 的 `MANAGED_EXECUTOR_IMAGE` 与挂载配置。
   - 切换后完成只读数据摘要对比、公网入口健康检查、管理员模型开关读写测试及新账号冷启动冒烟。

### 阶段 B：Phase 3 — 体验打磨与可控技术债演进（`.24` 上线后持续批次）

| 批次 | 工作主题 | 触发依据与实施边界 |
| --- | --- | --- |
| B1（体验优化） | 配额提示、本地/托管开发流、研究交付流打磨 | 基于真实用户使用 `.24` 的反馈，优化额度预占状态提示、模型探测报错可读性、`hosted-local` 代理构建与多模型切换引导；不放宽计量与来源校验 |
| B2（结构解耦） | `up.rs` / `store.rs` / `chat/mod.rs` 增量拆解 | 结合实际需求修改按领域拆出高内聚子模块（如 `commands/up/`、`store/research/`、`chat/` 的队列与运行期测试），每次拆分独立配齐 clippy 与完整回归，不做无业务伴随的大规模重命名 |
| B3（上游按需跟踪） | 评估 `v0.2.25` 剩余条件项及官方后续版本（`v0.2.27+`）小修 | 按实际复现评估 `#887`（Codex 相对配置）、`#720`（Windows 不可信链接回退）、`#890`（虚拟列表无障碍）、`#734`（云盘占位跳过）、`#897`（取消日志收尾）等补丁；不追逐提交数量 |

### 阶段 C：重型架构与高成本能力准入边界（保持按需立项）

以下方向继续执行**四要素准入**（明确受影响用户、真实复现/使用证据、最小交付改动、长期维护成本评审），未满足前不进入常规迭代：

- **上游大型架构重写**：`#862 orx-host` 新实验引擎（225 文件）、`#938` ACP 常驻代理体系、`#885` 新子代理协议、`#886` CodeMirror 输入器重写、`#891` 多机工作区切换、`#873` `.orx` 项目分享、`#877` `openresearch.sh` 云发布。
- **产品扩展专题**：PR `#17` 固定数据复跑（含冻结输入集删除保护语义）、跨 Run 指标趋势对比、完整环境镜像封存、签名桌面安装包（macOS/Windows/Linux 自有更新通道与签名链）。

每项需求提交四个要点：解决谁的现有问题、复现或使用证据、最小交付改动、长期维护成本。未明确的项保留待评估，不先扩展实现。官方版本号与本项目产品版本分别记录，不因官方升版自动变更本地功能范围。
