# 工作流节点扩展方案：条件分流、循环与执行节点

2026-11-16 · 提案已确认范围。P0 现状见 [节点契约](workflow-node-contract.md) 与 [节点库交接](workflow-node-library-handoff-2026-11-12.md)。

本文是 2026-11-16 与主理人确认的节点扩展范围：逻辑节点（分流、汇合、循环、逐项）、执行节点（实验、等待）、人工节点（人工任务）与展示辅助（阶段分组框）。每个节点先讲场景，再定画布形态与数据契约。

## 批次一完成证据（2026-11-17）

已实现：条件分流 route、汇合策略（等全部/任一完成）、失败兜底、阶段分组框、`skipped` 状态与传播。要点：

- 引擎：`TaskSpec` 新增 `kind/route/routeBranch/waitFor`（空值不序列化，已批准计划哈希不变，见 `legacy_specs_without_route_fields` 测试）；`Study::resolve_routes` 在派发、验收、返工与后台对账前求值；`ready()` 支持 skipped 满足与「任一完成」汇合；交付门与全部完成判定豁免 skipped；返工重置连同跳过分支与分流判定一起复活。
- 共享校验：`validate_route_rules` 同时把守草稿保存与计划提交（两条分支必须存在、来源必须来自开启把关的直接前置、分支标记只挂在分流下游、「任一完成」至少两条前置）。
- 前端：节点库新增「条件分流」「阶段分组」；连线自动标注「成立/不成立」；分流属性面板（判断依据/结论来源/分支走向）；任务属性面板新增汇合方式与分支走向；分组框支持拖动、缩放、重命名，只存画布坐标不进执行计划。
- 运行视图：跳过任务显示「已跳过 · 分流未走此分支」，分流节点显示判定依据，进度按「已完成 + 已跳过」计；主会话唤醒文案如实呈现跳过数量。
- 测试：Rust 全量 1560 项通过（新增分流/汇合/跳过/返工重路由/旧数据兼容等 8 项编排测试与草稿校验、往返测试），UI 全量 685 项通过，clippy 无警告。
- 浏览器验收（slot-1 隔离槽）：节点库条目、分流拖入与属性面板、连线分支标注、不完整分流保存拦截（大白话错误）、分组框选中/重命名/保存往返、服务端字段往返均通过；验收草稿已删除。验收中发现并修复两个集成缺陷：`WorkflowStudio.draftInput` 载入库中草稿时丢弃 `frames`；分组框以 `style` 尺寸渲染导致 reactflow 测量失败保持隐藏，改用节点 `width/height` 字段。

## 共同契约（先于任何节点实现）

1. **显式版本化节点类型。** 画布草案沿用单一 `tasks` 数组，每项增加显式 `kind` 字段（`agent` / `route` / `foreach` / `experiment` / `wait` / `human` / `loop` …），缺省视为 `agent`，旧草稿零迁移可读。备选方案是独立的版本化节点列表，若字段语义开始互相污染再切换，切换时提供读取兼容。不允许借 `role` 或自然语言简报伪装新类型。
2. **执行型新节点计入现有 40 任务上限；** 阶段分组框属展示层，上限另行评审。系统节点（G1/G5/G4/交付）继续由服务端派生，不进草案序列化。
3. **条件只认结构化结论。** 现状结论文件为 `{ verdict: "pass"|"blocked", reasons[] }`（`src/store/research.rs` `parse_verdict`，产物旁 `<产物>.verdict.json`）。首批条件白名单：结论为通过/阻塞、产物列表长度阈值；指标类阈值需先版本化扩展结论文件 schema，旧文件保持兼容，不允许模型自由文字判断走哪条。
4. **`skipped`、默认路径、汇合、失败传播一次定清。** 未被选中的支路标记跳过而非失败；全部条件不命中走默认出口；汇合点认"跳过"为已完成；失败与"结论阻塞"是两种状态，不允许阻塞门控冒充分流。
5. **红线继承 [节点契约](workflow-node-contract.md)：** 任一路径不得绕过预设必需审查与系统确认；不支持的节点类型明确拒绝保存；新配置进入计划等价比对与批准范围；重启恢复不重复已持久化成功操作。

## 各节点设计

### 1. 条件分流 route（批次一）

场景：检索完成后看命中量——够走精读，不够先扩检索式；或按材料类型分——论文走精读线、数据表走统计线。

- 画布形态：一个入口、两个出口（首批）；结构保留 N 出口，作为后续 switch 的自然扩展。未选中支路显示"跳过"。
- 条件来源：前置把关任务产出的结论文件，按白名单谓词判断。
- 与现有门控的关系：`gateDownstream` 是"不通过就卡住等人"，route 是"不通过就自动走另一条"；两者并存，把关任务可只挂分流，也可保持阻塞。
- 验收：未选支路状态可追溯；汇合不因跳过支路永久等待；默认出口必须显式存在。

### 2. 汇合策略（批次一）

场景：三位审稿专家并行，两票通过即可继续，不必三票全过。

- 形态：作为接收多条依赖任务的控制属性（同 `requiresApproval` 的位置），不改 DAG 结构。首批开放"等全部 / 等任一"，"多数通过（quorum N）"随后。
- 语义：按策略判定放行后，再进入该任务自身的结论把关与人工确认；`skipped` 依赖在"等全部"下视为满足、在"等任一"下不参与计数。
- 验收：旧草稿缺省策略等于现有"等全部"，行为不变。

### 3. 失败兜底（批次一）

场景：检索命中过少→换检索式重查；某专家超时→降级走简化版。

- 形态：与 route 共用一套 skipped / 汇合机制，只是谓词换成"上游执行失败或产物验收未过"。
- 首批范围：仅允许"失败→走指定兜底任务"，不做通用 catch-all 拓扑；工具或任务的失败不得伪装为分支 false 以外的静默忽略。

### 4. 阶段分组框（批次一，纯展示）

场景：几十个节点圈成"检索→精读→写作→审查"，一眼看懂分几步。

- 只存画布坐标（同系统节点坐标进 `positions`），不进执行计划、不参与批准与计划等价比对；旧草稿无分组正常显示；不改变 40 任务上限与依赖语义。

### 5. 逐项处理 foreach（批次二）

场景：对文献发现产出的论文列表逐篇精读，读完汇总。

- 列表来源：上游任务显式声明的列表产物（含每项结构声明），消费前校验；首批从"论文列表逐篇精读"真实场景切入。
- 循环次数 = 列表长度，天然有界。节点属性：并发度（默认 1）、部分失败策略（暂停 / 跳过继续）、汇总任务（固定接一个）。
- 实例建模：区分 attempt、iteration 与列表项标识（继承节点契约评审边界）；每项产物按项编号隔离。

### 6. 人工任务 human（批次二）

场景：从候选图里挑最终用的、给报告定标题、把线下拿到的数据传进来。

- 形态：画布显式节点；运行时在聊天收到任务卡，主理人提交文本或文件后产物进入产物清单与验收，流程继续。
- 需要独立的持久化暂停 / 恢复语义（节点库交接已指出）；人工任务的提交本身就是产出，不再叠加第二套批准；W1 必需审查与系统确认红线不变。

### 7. 实验节点 experiment（批次三，P1 固定工具首例）

场景：把实验提交到服务器或沙箱真跑，等指标和日志回来再继续，失败可重跑。

- 与固定工具的区别：工具是秒级确定操作（解析一份 PDF），实验是小时级长任务，有日志、指标、状态与失败重跑。
- 契约：操作标识与版本、输入走登记材料 / 产物引用（版本 + 哈希）、输出产物与指标文件、权限范围与副作用状态记录；失败不伪装为分支 false；重启恢复不重复已持久化成功操作。
- 执行后端对接（沙箱 / 服务器队列）另行评审，本节点先定数据契约；具体案例建议从"提交实验 → 等待 → 取指标"一条链做起。

### 8. 事件等待 wait（批次三）

场景：等服务器上实验产出文件出现再继续；等次日才发布的数据。

- 形态：等待对象为登记产物路径（哈希变化视为到达）或时间点；超时定义为阻塞（转人工处理），不静默失败。依赖实验节点落地后实施。

### 9. 有限循环 loop（批次四）

场景：检索→查量→不够→改检索式→再查（循环体包含判断本身）；写→审→改到过为止。

- 形态：容器节点，循环体为容器内子图；容器属性为退出条件（复用条件白名单）与最大轮数硬上限（独立于 `MAX_REWORK`，默认值与上限值在实现评审时定）。
- 每轮产物独立版本，分清 attempt 与 iteration；允许的回边只存在于容器内，不放开当前 DAG 的任意回边。
- 最后实施：成本最高（轮次、版本、退出条件全量建模），且现有"有界返工"（`gateDownstream` + `max_rework`，上限 3）已覆盖最常见场景——它等价于"打回上游重做"的固定形态循环，本节点补的是"判断在循环体内"与"轮次显式可见可控"两类缺口。

## 实施顺序与理由

1. **批次一**：条件分流 + 汇合策略 + 失败兜底 + 阶段分组框。分流是全部分支语义的地基，skipped、默认路径、汇合必须一次定清；分组框纯展示，可先行或同批交付。
2. **批次二**：foreach + 人工任务。foreach 复用批次一的汇合语义并建立"轮次"概念；人工任务补"人往流程里放东西"的空白。
3. **批次三**：实验节点 + 事件等待。执行契约最重，作为固定工具线的第一个真实案例推进。
4. **批次四**：有限循环。

每批验收继承节点契约与节点库交接：旧草稿与旧计划可读可用、行为不变；不支持类型明确拒绝；工具结果可追溯到输入与版本；任一路径不绕过预设必需审查、实验限制与系统确认；按 CI 检查并重建 `ui/dist`。
