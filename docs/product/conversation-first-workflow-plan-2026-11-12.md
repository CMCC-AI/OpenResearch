# 对话式工作流运行（已实现）

2026-11-12。用户明确方向：通过与 AI 对话提供输入，由 AI 执行工作流，专家的过程与输出在当前聊天中展示。用户随后指示“改吧”，本轮已实现以下范围。

## 产品决定

- 主入口是现有聊天框。自然语言需求、补充约束及共享上传入口提供的材料引用共同构成本次运行输入；普通交流继续保持普通对话，不要求上传。
- “研究输入”不再作为画布节点显示；旧坐标兼容保存。引擎仍保存可追溯的运行输入和材料范围，当前画布从范围确认开始。
- 工作流编辑器负责定义可复用的方法。运行时使用聊天上下文绑定目标与材料，不要求用户离开当前对话去另填目标表单，也不默认另开主会话。
- 用户可以指定已有工作流，AI 也可根据明确任务匹配工作流库；无法确定流程或缺少关键输入时，在当前聊天澄清。流程选择、版本与本次范围须清晰可见。
- G1、任务后确认和 G4 继续由既有服务端契约控制，在聊天内显示范围确认、任务确认和交付确认卡片；卡片绑定现有决定与实际版本，不另建聊天专用批准状态，也不由 AI 代替人工批准。
- 专家任务进展、工具活动、过程摘要、证据、阶段结论和最终产物汇入主聊天。默认给出简洁进展，可按专家/任务展开；并行专家保持各自身份与顺序，不混为同一段文本。
- 用户所说的“思考过程”落实为面向用户的工作过程与判断依据摘要。底层可用的进展内容据实展示；不编造未上报过程，也不承诺所有执行后端都提供完整内部推理。当前聊天渲染器不展示 reasoning parts。
- 子会话保留为执行与审计记录；主聊天能够阅读关键过程与完整交付，打开子会话或 DAG 是补充查看方式。产物保持原文件、哈希、来源与版本，聊天显示正文或预览并提供原文件入口。

## 实施范围与验收

### 1. 当前聊天绑定工作流

接入已有工作流选择/匹配、输入整理和范围确认，保持当前会话及已有消息；保存工作流版本和输入快照，重复提交去重。

验收：在已有项目对话中说“用某工作流分析这些材料”，能够在该会话看到流程和范围卡片；批准后开始执行，主会话 ID 不变；补充约束可更新未确认输入，已确认范围变化沿用现有修订机制。未具备关键输入时明确提示；普通聊天不强制进入研究。

### 2. 专家活动汇入主聊天

复用现有子会话执行。按研究、计划版本、任务、attempt 和稳定事件 ID 归属活动；事件保留顺序，可持久化、去重并断线续接，避免把子会话全部内容复制为匿名主理人发言。

验收：至少两个专家并行时，用户可在主聊天分辨执行者、当前工作和阶段结果；刷新后不丢失、不重复；重试和返工可辨识轮次；缺少过程正文的后端显示已知活动与最终报告，不编造过程。

### 3. 确认与成果留在对话

将既有确认卡片、任务状态及产物预览嵌入消息流，支持文件入口和最终报告。确认按钮调用原决定接口，保留 scopeHash 和计划版本校验。

验收：G1 前不派发；任务后确认前不放行相应下游；失效的批准不能复用；G4 前不显示已确认交付。失败、补材料、取消和恢复都有对应状态；最终正文/预览及文件在当前聊天可见，来源与产物版本可追溯。

### 4. 收拢画布入口

移除节点库中的“研究输入”入口与强制展示节点，必要的入口锚点由系统维护；独立使用页面可保留为选择快捷入口，但应把流程带回聊天完成运行配置与执行。

验收：旧草稿可打开保存，忽略或清理旧输入节点坐标不改变专家任务、依赖和批准范围；旧研究仍可读。全局与项目入口、普通对话、材料共享上传不回退；在隔离 slot 完成宽屏、窄屏和收起侧栏验收，重建 `ui/dist`，执行相应 CI 检查。

## 顺序与边界

上述聊天运行链路已实现。原 [P1 工具与条件分流](workflow-node-library-handoff-2026-11-12.md) 仍为后续计划；之后增加的工具、条件、批处理及循环定义执行方法，运行过程与成果统一通过聊天展示。

## 实现与验证

- 主聊天使用方法：`orx research workflow list/show/use`；普通聊天可在原会话绑定计划，去重并固定方法来源、目标与材料。来源快照进入 G1 范围；改目标不继承旧问题产物。见 [CLI](../../src/commands/research.rs)、[计划登记](../../src/store/research/plans.rs)、[CLI 集成测试](../../tests/workflow_conversation_cli.rs)。
- 聊天展示：读取原专家会话消息，使用现有 SSE、分支指针与查询缓存；按任务、版本及尝试展示，不复制成匿名主理人发言。过程展开、历史执行、停止专家、产物哈希校验和报告正文均在聊天中。见 [ResearchConversation](../../ui/src/components/ResearchConversation.tsx)。
- 确认与交付：聊天中的确认卡片复用原决定接口及 scopeHash；匹配的当前研究包确认后才提供确认包下载。证据变化不会继续显示完成状态。见 [ResearchPanel](../../ui/src/components/ResearchPanel.tsx)、[对话状态](../../ui/src/researchConversationStatus.ts)。
- 入口：画布目标表单及可见输入节点已移除；工作流库选择和聊天选择器只准备草稿，不自动发送、不另开主聊天。见 [工作流选择器](../../ui/src/workflow/WorkflowPicker.tsx)、[聊天交接](../../ui/src/workflow/conversation.ts)。
- 624 项 UI 测试通过；Rust 全量 1567 项通过、14 项忽略。类型检查、构建、Clippy、格式、样式及包体积检查通过，`ui/dist` 已更新。浏览器覆盖双专家、SSE 增量与断线重连、刷新去重、G1/G5/G4、报告正文、失效证据与多宽度。见 [完整验收记录](../../output/playwright/conversation-workflow/verification.md)。

验证使用隔离数据和浏览器夹具，未调用真实模型、未执行真实研究或实验，未部署服务器。自然语言匹配通过现有 Agent 引擎调用新 CLI；本轮不声称验证了某个模型的语义选择质量。
