# 私人空间与系统权限

产品身份只有普通用户和系统管理员，以 `platform_users.is_admin` 区分。系统管理员可以管理账号概况和精选案例；管理员身份不赋予他人私人研究空间访问权限。

私人空间以 `workspaces.created_by` 的用户 ID 为唯一归属依据，列表、进入凭据、HTTP、SSE、WebSocket、运行环境、偏好和文献 SSO 均验证归属。删除成员角色判断后，即使历史成员被记录为 owner，也不能访问其他人的空间。新建空间不再写入成员表，接口不再返回空间角色。

已移除成员列表、角色变更、成员移除、邀请创建/列表/撤销/接受及前台接受邀请逻辑。旧链接和接口不能继续授权或注册账号。`memberships` 和 `workspace_invites` 表及原迁移保持不变，仅作为历史与回滚资料；不执行破坏性删表。迁移前已建立的非创建者会话也无法再访问研究接口或续用文献 SSO。

注册会在同一事务内创建 `personal_spaces` 唯一归属记录；空间归属不依赖计算资源是否已启动。既有账号通过离线 `ensure-personal-spaces` 幂等补齐。普通用户不需要创建、选择或管理工作空间。

首次进入研究页面时自动准备独立 Docker 运行环境与用户数据卷；后台、精选案例和论文精读不要求先分配科研计算资源。容量不足或环境失败只影响计算准备，不删除账号或个人数据，可重试。用户管理不展示空间数量。

IP 部署使用 `PRIVATE_SPACE_ROUTING=shared-origin`，同时启用 `PRIVATE_USER_SPACES=true` 与 `MANAGED_EXECUTORS=true`，应用 origin 必须与账号 origin 相同。网关将科研 API、SSE、终端交给账号平台，服务端只按当前会话用户查找私人空间并转发专属执行器，客户端不能指定其他用户的执行器；账户 Cookie 不转发给执行器。不依赖 UUID 子域名或额外公网端口。

现有指定研究账号保留原工作台及数据挂载，仅增加专属连接器；其他账号使用互不重叠的 Docker home。管理员 OpenCode 设置与模型授权在首次启动时复制到私人目录，后续不覆盖用户数据。供给服务独立持有 Docker socket，科研容器不持有 Docker socket、不发布端口。服务器容量由管理员配置，默认激活容量为 6 个运行环境，包含原账号。

管理员可以在用户管理中为用户设置新密码，必须验证自己的当前密码；新密码采用与注册相同的强度要求和哈希存储。事务内验证管理员权限、更新密码版本，撤销目标用户全部会话和未使用找回链接，并终止关联流。文献 SSO 授权随根会话失效。修改自己的密码会要求重新登录。审计仅记录操作人与目标用户 ID，不记录密码。

精选案例是管理员审核后发布的独立公共快照。所有登录用户可查看已发布案例与副本文件，不因此获取原项目权限；普通用户没有发布入口。

验证使用独立测试 PostgreSQL：覆盖三个旧角色均不能跨空间访问、管理员无私人数据特权、旧成员会话被拒绝、全部团队接口不可用、个人空间重复创建幂等及 HTTP/SSE/WebSocket 和退出撤权。部署前备份 PostgreSQL 和研究 SQLite，保留旧容器与镜像。

已有账号可通过受控服务器终端执行 `node src/admin.mjs grant-admin EMAIL` 授予系统管理身份，不重置密码；停用或不存在的账号会被拒绝，重复操作幂等并记录首次授予的审计事件。该命令不开放浏览器接口。
