## 原始目标与核对范围

目标：A、审查工作流、Skill 和智能体创建界面；B、对照 Alpha Data 的视觉与交互；C、给出有证据、可执行的优化建议。

本地使用浏览器内的临时展示身份读取现有开发数据，同时拦截该页面所有非 GET/HEAD 业务请求。没有保存工作流、创建智能体、上传技能或启动生成/实验。页面中显示的 3 条工作流、23 个专家、16 个技能和 1 个 MCP 来自既有开发槽，数量只描述本次检查时的样本。

已查看：工作流库、空画布、Agent 创建表单和 AI 创建浮层、Skills 库、用户技能详情及生效范围；画布覆盖 1440×900、1024×768、1024×768 收起导航、390×844。没有将登录页、报错页或开发工具面板当作产品内部界面证据。

证据截图位于仓库本地的 `output/playwright/workflow-ui-review-2026-11-25/`（已被仓库忽略，非发布资产）；下文截图链接相对该文档可在本机打开。源码位置对应本次检查状态，后续改动可能使行号变化。

## 结论

现有蓝色主题、图标与基础卡片可以继续沿用。优先改善入口层级、创建路径和画布空间分配，再统一排版、按钮与状态表达。单纯增加颜色、阴影或插图不能解决当前的操作成本。

对照边界：Alpha Data 当前账号没有已有团队，实际画布必须先创建团队才能进入，本次没有创建，因此没有比较其节点画布、执行、保存和运行结果；Skills 核对的是 Agent 中的技能选择，不冒称完成了独立技能编辑器审查。以上边界不影响入口、起步表单、能力选择及本项目画布问题的结论。

## 候选实施计划（等待用户启动）

目标：让用户从资源库找到合适能力，通过统一的创建过程形成草稿，并在宽屏和窄屏持续完成编排与使用。

1. **资源入口**：F1、F5、F6。工作流库层提供资源导航和直接链接；智能体和技能可搜索；在调整页面挂载方式时定义好未保存草稿的恢复行为。验收重点：无需先新建工作流即可管理资源，刷新和返回位置正确，切标签不静默丢稿。
2. **创建与选择**：F4、F7、F9。新建工作流提供 AI/模板/空白三种起点；Agent 创建提供起草/手动配置与职责、技能、工具分组，底部操作保持可达；技能与工具使用可搜索的选择器，主表单展示已选摘要。复用现有 AI 生成、角色 prompt 和对话登记能力。验收重点：从科研场景进入草稿，采用前可审阅，失败可恢复，绑定语义准确。页内技能编辑器不默认包含在本计划；其内容校验、版本和登记接口需另定范围。
3. **画布与视觉收尾**：F2、F3、F8。属性栏按需出现，节点库可折叠/搜索，窄屏使用抽屉和点击添加；统一卡片、表单组、按钮及空态。沿用 `bg-background`、`text-subtext`、`border-border` 等主题别名和既有图标。验收重点：空属性栏不占位，1024px 首屏保留画布，390px/320px 主要控件可达，拖拽、连线、自动保存和“在对话中使用”保持正确。

每一步均以上述发现对应的验收标准为完成条件。实施后补齐工作流库、空/已有画布、Agent 手动/AI 草稿、Skills 列表/绑定详情的截图；覆盖 1440、1024、768、390 和最窄 320px，含展开/收起导航、键盘操作、空数据、加载和真实错误反馈。只为实质行为写必要测试，例如草稿保留、路由恢复和绑定状态，避免仅镜像样式实现的测试。

UI 改动完成后运行仓库要求的 i18n/style 检查、相关现有 UI 测试和 `pnpm build`，包含重新生成的 `ui/dist`。交付前按 `.github/workflows/ci.yml` 和 AGENTS.md 执行适用完整门禁；如果涉及 Rust，遵循先检查其他 cargo 进程、迭代用相关 bin 测试、交付前全量 `cargo test --locked` 的要求。当前仅审查文档，没有宣称通过 UI 构建或 Rust 测试。
