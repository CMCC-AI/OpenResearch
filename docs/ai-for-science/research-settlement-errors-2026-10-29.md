# 专家收尾的持久化失败与数据异常（2026-10-29）

本批基于 `a6e1789`。检查发现 `on_research_spawn_finished` 会忽略提醒、重试、
失败验收和交付确认的部分落盘错误，之后仍可能返回 RetireSilently 或 WakeLead。
任务可能继续是 running，但运行中的 spawn 已被后台收尾；交付提示也可能早于真实确认记录。

## 复现与修复

用临时 SQLite 触发器拒绝 research_studies UPDATE：修复前，提醒落盘失败仍得到
`Ok(Some(RetireSilently))`。另一个回归验证当前 Run 缺失时，原活动运行检查返回 false。
修复前两项回归均失败，短期记录为 `/tmp/orx-settlement-before.log`。

- 专家完成标记、提醒、重试和失败验收必须确认存储成功，才返回下一步动作。
  自动验收遇到 SQL 错误直接上报，不再把它当成缺少产物并消耗提醒／重试次数。
  正常缺失或旧产物仍保留原来的提醒与有限重试流程。
- 当前任务的 Run 必须存在且结束；缺失 Run 不得被视为无活动运行，也不能在重试中
  被静默归入旧运行历史并清除当前契约。重复查询改为一次加载后判断。
- 研究读取错误附带研究 ID 和解析原因；当前绑定缺少研究／任务时上报，
  stopped、旧版本或已替换绑定仍按原有语义退休，不恢复旧研究。
- 运行中 spawn 的阶段工作保留 Store 和错误结果；单个研究的数据错误记录到既有日志，
  保留该 spawn 供后续处理，并继续其他 spawn。SQL 错误中止本轮存储阶段，等待下次巡检，
  不把失败动作当成已完成。没有增加新通知系统或无限模型重试。
- 后台巡检和专家收尾共用交付结果持久化：只对 active 的同版本研究更新
  delivery_error、申请或失效确认记录。失败时不缓存成功检查，也不通知主会话“已申请”。
  发出主会话动作前再次确认研究仍有效。

## 回归范围

故障注入覆盖提醒、失败验收、重试、自动验收、交付申请、交付失效六个阶段。
断言失败后研究及尝试次数不变、spawn 未退休；解除故障后原动作可重试成功，
没有提前创建替代专家或伪造交付确认。

另验证缺失 Run 拒绝重试、损坏聚合报告研究 ID，以及坏研究排在前面时，
后面的独立普通 helper 仍可正常退休，坏 helper 不产生新的原生 turn。
测试仅操作隔离 Store，不调用真实模型。

## 保留边界

错误日志和现有研究状态错误入口承担诊断；没有自动修复损坏记录、删除引用或扫描全库。
没有收尾 spawn 的损坏文档仍沿用现有 active 查询行为，本批不声称建立完整数据健康面板。
发生进程崩溃时仍依赖已有 claim、finished_at、nudge 和回执恢复规则。
文件内容和多进程变更并未成为原子快照，交付批准仍须重新核验完整范围。
历史 Run 审计范围、回收策略和跨进程工作区协调均未改变。
