# 旧工作区迁移的会话锁隔离（2026-10-29）

接续 `cc0b000` 的研究结束入口，处理 TD-05D：`ChatHost::while_idle`
原来在全局 turns 锁内逐会话打开 Store，并同步运行 Git worktree 迁移。
慢磁盘或 Git 会阻塞异步线程及不相关会话；简单解锁又会让新 turn 在迁移期间进入。

## 本批行为

- 在全局 turns 锁内仅检查受影响会话，取得其已有 cleanup gate，
  并写入带唯一 token 的 Migrating 占位，然后释放全局锁。
- 数据库租约查询和实际迁移使用现有有界后台池；不新增线程池、调度器或全局工作流。
  重复会话 ID 去重；空会话列表的回调同样不持有全局锁。
- 实际 worker 持有占位及 cleanup gate。等待者取消不会提前开放工作区；
  存储错误、回调失败或 panic 均释放自己的占位，清理不会覆盖其他 token。
  清理遇到 turns 争用时异步等待，不阻塞后台 worker 完成。
- Stop 不把迁移占位改为 Cancelling；删除在操作工作区之前拒绝迁移中的会话。
  迁移开始／结束发出既有 chat.busy 事件，避免期间读取 busy 的客户端停留在忙状态。
- `Store::chat_turn_leased` 对缺少租约返回 false，对真实 SQL 错误返回 Err，
  不再把损坏或查询失败误认为可以迁移。

## 发布请求的生命周期

发布调用使用拥有项目 admission 的独立任务，内部持有已有 publication lock。
HTTP 断开不能让项目删除或数据目录移动越过仍在执行的迁移和发布；
自动重启也检查项目操作计数。取得 publication lock 后重新读取项目，
避免排队请求使用旧的远端信息重复创建仓库。

旧路径检查、浅克隆发布准备、必要的 reroot 及发布元数据写入进入后台池。
保留既有 GitHub 发布和 push 的调用条件，不新增发布入口或自动发布策略。

## 验证边界

新增 `idle_migration_tests.rs` 使用真实隔离 Store 和人工挂起的存储／Git 回调，
验证单线程 runtime 的 timer 及其他会话 claim/release 可以继续；
取消等待者、内部 interrupt、用户 Stop、删除与自动重启检查均不能释放工作区保护。
另覆盖外国租约、SQL 查询失败、回调失败／panic、重复 ID 和清理锁争用。

这些是故障注入回归，不是实际 Git 命令或线上负载的性能测量。
本批保持既有跨进程租约检查，未新增跨进程 worktree 迁移租约；
两个独立进程同时迁移同一物理工作区的协调仍不在本批保证内。
Git 命令本身的超时和崩溃后的部分迁移恢复沿用既有行为，不宣称已治理所有同步入口。
没有调用真实模型、创建远端仓库、push 或部署。
