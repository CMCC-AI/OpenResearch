# 租约心跳隔离与过期结果保护（2026-10-25）

本批接续 TD-05，仅处理 `watch_runs` 的聊天租约心跳。产品版本仍为 `0.2.21-mobilesci.1`，不改变上游 partial 回移状态。

## 问题与实现

此前每 3 秒在异步巡检任务内直接 `Store::open`，顺序续租当前所有 turn；没有本机租约时也打开数据库。慢 SQLite 或锁等待会占用异步调度线程。

- 将续租快照交给既有 8 并发有界执行池；空快照直接返回，不打开存储。没有新增线程池、巡检或重试队列。
- 数据目录 gate 使用 owned guard，随任务进入实际 worker，正常返回后交回巡检以继续保护后续扫描。等待者取消时仍须等实际数据库任务结束才能迁移目录。
- 失去所有权的结果携带 `(session_id, token)`。中断前在全局 turn-map 锁内核对当前 token，并在同一临界区进入 Cancelling，防止旧续租结果误停新 turn。普通 Stop 复用既有结算流程。
- 续租 SQL 错误仍不判定为所有权丢失。打开存储或执行池失败会记录错误并跳过本次巡检，3 秒后的既有循环重试；不主动打断任务，也不新建重试机制。

## 自动化证据

新增四项测试覆盖：

1. 空闲续租不打开存储，返回的目录 gate 保持互斥。
2. 单线程 Tokio 中人为阻塞 Store opener，定时器及 turn-map 仍可用；取消等待者后，迁移 gate 保持锁定直至实际 worker 完成。
3. 旧续租阻塞期间替换数据库与内存租约，新 turn 保留；旧结果返回旧 token，中断返回 false，既不清除新占位也不广播 busy 事件。
4. 真实 SQLite 过期心跳被刷新；打开失败与注入 SQL 错误不报告所有权丢失，gate 在结束后可重新获取。

验证通过：Rust **1283 项单元、18 项集成**，11 项专用测试忽略；`cargo fmt --all --check`、`cargo clippy --all-targets -- -D warnings`、`cargo build --locked`、上游基线核查及 2 项产品版本测试通过。未改 UI，沿用上一批 UI 验证，不将其计为本批重新验收。测试使用隔离临时 Store 和合成阻塞，不代表生产负载吞吐提升比例。

本地日志为 `/tmp/orx-lease-heartbeat-{full,clippy,build,fmt}.log`；候选与源码/日志哈希记录在被 Git 忽略的 `.mobilesci-run/lease-heartbeat/evidence.json`。
