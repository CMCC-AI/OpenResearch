# Run 输入契约实施记录（2026-11-07）

状态：`feat/run-input-contracts` 基于产品 `f0f39e62` 的在制分支。当前实施的是描述符、数据库与恢复写回的身份保护基础，尚未提供输入启动参数、接入 G2/G3 或本地投递。不能将本节计作运行时输入契约、实际消费或新发行已完成。

## 本批身份保护

- BackendDescriptor 显式保留 `inputSet: { id, manifestSha256 }`，解析拒绝该对象中的未知字段；无输入时不序列化该键。所有后端构造点仍显式使用 None，未开放未经投递验收的启动能力。
- 新绑定只允许在 starting Run 首次插入时建立，要求同项目 frozen 集合、匹配的清单摘要、实验归属、非空命令及代码版本，并具备代码归档摘要、大小和路径。不根据这个关联推断程序已读取数据。
- 数据库触发器保护输入、项目/实验/会话、命令、代码版本及归档身份，覆盖 upsert、set_backend_json 和旧式原始 SQL。禁止后补输入身份；已绑定 Run 暂不支持删除，等待受保护生命周期设计。状态、取消意图和后端句柄仍可按既有规则更新。已有 Run 的身份保护不重新依赖可能变化的实验元数据，避免阻断取消。
- 恢复文件按当前 Store 绑定的数据目录读取，匹配 SQLite 预约的输入、代码和后端种类。记录句柄时，输入绑定写入失败或明确的身份约束错误直接返回；不能再把这些错误降级为缺少身份的“成功”恢复 JSON。无输入的既有数据库故障恢复路径保留。

触发器保护正常旧写入器，不能防御有权删除触发器、替换整个数据库或任意修改宿主文件的操作者。代码字段是固定身份元数据，本批没有新增代码原件验证或完整环境封存。

## 验证范围

八项定向回归使用真实材料冻结副本及显式合成 Run 元数据，未启动实验。覆盖描述符往返、同项目 frozen 准入、旧 SQL 丢字段/改来源、INSERT OR REPLACE（含关闭 recursive_triggers）、晚绑定、重开数据库、正常终态写回和取消、恢复身份不符、禁止恢复降级，以及无输入的旧故障恢复路径。最终完整八线程本地回归通过 1517 项单元、35 项普通 CLI，13 项单元及 1 项外部 PDF 忽略不计通过；八项定向回归、全目标 Clippy 零警告、格式及文档链接检查通过。尚无本批远端完整 CI 结论，不沿用 PR #16 的检查。

## 后续实施与验收

1. 接通 CLI/HTTP 与 G2/G3 的同一输入身份；旧无输入审批字节保持兼容，输入变更须重新准备和批准。客户端需先确认旧服务具备协议能力，防止旧 HTTP 服务忽略新请求字段后仍启动。
2. 本地投递按每 Run 独立副本实施，将实际逻辑文件字节（别名分别复制则分别计量）、清单与在途量纳入并发容量预约；与已有冻结副本合并检查同一显式配置上限。新数据库约束还须阻止旧冻结写入器忽略投递量后超额准入。不能在已有副本池之外无计量复制，也不能用共享可写原件冒充独立投递；中断占用、租约及显式恢复必须一起实现。该计量仍不覆盖整个工作区。
3. 本地真实进程校验接收字节后，从约定路径读取冻结后原件已改变的输入。该验收只证明这个受控程序；任意用户程序的实际消费能力仍需独立观测方案。
4. 未接入后端在启动和收费前拒绝显式输入；逐个完成其他后端传输、恢复及失败证据，不能把拒绝支持计作投递实现。
5. 最终功能候选通过自己的完整模拟合并 CI 后再合入、清理分支及冻结发行；生产候选仍须本版具体授权和独立恢复/入口验收。

与初始计划对照：首批官方回移和 `.6` 发行保持已完成；本分支继续来源链与运行时输入方向，不重计这些旧成果。全局总配额、材料/Run 生命周期、完整代码/数据/环境封存及生产升级保持未闭合。完整阶段划分见[输入冻结方案](run-input-freeze-plan-2026-11-07.md)。
