# 性能治理第十一批：outbox 扫描与文件清理测量（2026-10-23）

基线 `0ef8c91`。本批先测量收尾文件操作，再处理 outbox 选择的空间开销和异步入口的同步阻塞，功能扩展与服务器部署继续暂缓。

## 结论与改动

- outbox 原路径收集并稳定排序所有 JSON 路径，实际只重试最旧的 20 项。新实现以容量至多 20 的最大堆保留重试窗口，选择阶段由 O(N) 保留项降为 O(20)，仍需遍历并读取 N 项元数据；没有声称减少 stat 次数或整个遥测流程的内存上限。
- 排序键缓存每项 mtime，包括读取失败时的 None；枚举序号作为相同 mtime 的次序。保留旧稳定排序的结果、20 项重试窗口和缺失文件处理方式，不重排相同时间项，不改变临时文件过滤、无效 JSON 清理或事件 ID 去重。
- 聊天普通结束、中断、dashboard 定期重试及 CLI 异步退出入口改为等待有并发上限的后台准备任务；数据库待发送事件转移、目录扫描、stat、JSON 读取和投递任务注册在后台执行。网络任务仍注册到既有 pending 集合，退出时沿用原 flush 窗口。
- 同步启动入口继续保留。开发构建和运行时禁用遥测时，异步入口在不读取磁盘、不获取 blocking permit 的情况下返回；后台也保留原有资格检查，没有扩大遥测启用范围。
- 目标事件指针清理只提取可指定路径的内部函数用于隔离测量，执行位置不变。本机样本开销较小，且读指针再删除不是原子操作，本批没有通过额外异步窗口扩大交接风险，也没有宣称关闭这个并发边界。

## 本机测量

使用独立临时目录，不读取业务数据、不启动模型、不向外部遥测端点发请求。debug 构建；outbox 每组 10 次、三轮交替顺序，校验新旧算法选出的路径完全一致。下表为每次选择的轮均值范围：

| JSON 文件数 | 原稳定排序 | 保留 20 项的堆 |
| --- | --- | --- |
| 2,000 | 5.98–6.62 ms | 5.46–5.82 ms |
| 10,000 | 36.58–38.78 ms | 34.60–40.12 ms |

这只测量路径复制、stat 与选择，不包括目录枚举、pending telemetry 转移、JSON 读取和网络。1 万项存在新算法更慢的轮次，不能据此报告稳定延迟提速；明确收益是选择阶段保留项数有界，以及异步路径不再在运行时工作线程执行这些同步操作。当前源码默认开发构建本就不扫描遥测，这些 outbox 改动不能解释为本地聊天已获得相同幅度的提速。

目标事件清理测量 200 次：均值 **0.0855 ms**、P95 **0.1073 ms**、最大 **0.2129 ms**。计时覆盖删除事件文件、读取并核对指针、删除匹配指针，排除测试文件准备、路径编码和断言。该结果来自本机临时目录，不能外推慢盘或服务器尾延迟，因此本批保留该操作原位置。

## 验证

- 选择结果与旧稳定排序对照，覆盖空输入、0/1/20/全量/超量窗口、缺失 mtime 和大量相同时间项；每个输入文件的元数据只读取一次。
- consent 回归改为在单线程运行时通过实际后台扫描注册投递，并使用本地 HTTP 监听器验证 consent 事件删除、opt-out 下产品事件仍保留；测试显式调用扫描内核，不改变生产构建资格检查。
- 指针测试验证旧目标不会删除已指向新目标的指针、匹配时删除、文件已不存在时可重复清理。这不是并发原子性测试。

最终验证通过：`cargo fmt --all --check`、`cargo clippy --locked --all-targets -- -D warnings`、`git diff --check` 均通过；完整 `cargo test --locked` 退出 0，1226 项单元测试、18 项集成测试通过，10 项专用测试默认忽略。两项新增专用测量均另行显式运行并通过，其他忽略项不计为本轮已运行。outbox 测量完成后只调整了对照测试中的 Clippy 写法，最终完整回归覆盖最终源码。
