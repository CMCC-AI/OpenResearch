# 性能治理第九批：收尾租约释放（2026-10-23）

基线 `8bec037`。本批仅处理 `finish_turn` 不保留队列槽位时的租约释放，功能扩展与服务器部署继续暂缓。

## 实施范围

- 原路径持有全局 turns 锁同步打开 Store、删除租约。本批在该锁内安装带唯一标识的 Releasing 槽位并取出当前令牌，随后由独立持有的异步任务通过现有 8 并发 blocking 执行池完成打开与删除。存储执行期间不持有 turns 锁。
- 数据库删除仍限定 session ID 和捕获的 claim_token。后台完成后只移除相同 release_id 的槽位，再广播会话空闲；替换后的槽位、内存令牌和数据库新租约均不由旧任务清除。
- Releasing 期间会话保持 busy，队列不能提前取得槽位；Stop 返回 false 并保留该收尾占位，因为生成任务已结束。原有队列可继续时仍直接进入 Draining，不释放租约，也不走新的后台释放路径。
- 等待者取消不会取消独立清理任务；无 durable token 时不打开 Store。打开或删除失败仍按原来的 best effort 释放内存占位，数据库残留租约依赖现有过期机制，本批没有新增持久重试保证。

这里没有把整个 finish_turn 机械移入后台：会话 touch、spawn 完成标记和快照读取的归属条件需要另行处理。本批引入的等待点不持有全局 turns 锁，也不改变其他 release_durable_turn 调用者。

## 验证

新增三项回归测试，使用独立临时数据库：

1. 慢打开期间单线程运行时计时器仍推进，可取得 turns 锁操作其他会话；当前会话仍 busy，Stop 不破坏占位，队列不会提前启动。释放完成后数据库租约消失，并且只广播一次空闲。
2. 模拟旧释放任务延迟期间替换槽位和令牌，旧任务不删除新数据库租约、不清除新内存状态，也不广播迟到空闲。
3. 没有令牌时不调用存储打开函数；取消等待者并注入打开失败后，独立任务仍完成内存占位清理。

最终验证通过：`cargo fmt --all --check`、`cargo clippy --locked --all-targets -- -D warnings`、`git diff --check` 通过；完整 `cargo test --locked` 退出 0，1220 项单元测试及 18 项集成测试通过，8 项专用测试默认忽略。本轮没有复跑忽略的压力基准。最初三项针对性测试通过后补充了广播断言，最终完整回归覆盖这些断言。
