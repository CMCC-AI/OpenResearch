# 科研专家团原版预设流程

2026-10-16：新建研究分为“工作模式”和“科研专家团模式”两个大类；科研专家团模式默认由主理人自动判断执行路径，同时允许手动指定原版主理人提示词中的四个预设流程；替代此前自行设计的方案、诊断、审稿三个会诊入口。旧记录及其计划继续可读、可推进，不自动改写历史。

| 流程 | 核心路径 | 执行与交付边界 |
| --- | --- | --- |
| W1 系统文献综述 | 检索策略 → 文献发现 → 逐篇证据 → 综合 → 大纲与写作 → 独立审查与引用审计 → 归档 | 跳过方法和实验专家组；G1 确认范围、G4 确认交付 |
| W2 论文复现 | 可行性与材料审计 → 论文声明 → 复现设计 → 代码 → 真实运行 → 对比分析 → 报告与审查 → 归档 | G1 确认范围；运行前 G2/G3 绑定版本、命令和资源；G4 确认交付 |
| W3 实验数据分析报告 | 资产审计 → 结果分析 → 大纲 → 正文 → 图表引用编辑 → 独立审查与引用审计 → 归档 | 分析已有数据和日志，不自动补跑实验；G1/G4 |
| W4 Idea 到实验方案 | 可行性 → 文献验证新颖性 → 方法设计 → 实验设计 → 方案交付 | G1 确认范围；已完成的 Experiment Plan 经 G3 确认后交付，不运行实验 |

依据原版 `.opencode/experts/ai-for-science-team/agents/ai-for-science-team-team-lead.md` 的预设 Workflow，通用研究诚信规范要求 W1–W3 独立审查及引用审计；W4 按原预设在方案交付处结束。W2 的失败诊断按实际失败触发，保留真实日志，通过有限 REFINE、版本化 PIVOT 或 STOP 处理。

原版流程适配原生执行底座：W2 的 G2/G3 由 `prepare-run` 在代码提交后统一绑定实际运行契约，不将提示词里的确认替代为运行授权。为保证批准绑定完整文件，原生归档专家先整理包内容，再由 G4 确认该版本。W4 的 G3 则校验已经验收的方案产物，批准不授予实验执行权限。

## 统一定义与执行

`ui/src/researchWorkflows.json` 是四个流程的共同定义，包含目标、输入、交付、必需角色、禁用角色、关键依赖、执行权限与最终确认节点。前端直接展示该定义；Rust 编译时嵌入同一文件。自动判断会话每轮注入全部流程及语义触发条件，主理人在版本化计划的 `workflow` 字段登记所选流程，并在摘要中解释依据；综合任务可保留空值，动态安排必要专家。手动指定会话每轮注入指定流程，不允许计划暗中改成其他流程。匹配预设后，计划登记验证该流程的必需角色、依赖与执行边界。

用户可以在首页、新对话中先选择“工作模式”或“科研专家团模式”；选择专家团后默认“自动判断”，也可通过独立的“执行流程”选择器指定四个流程之一，选择随草稿和附件保存。已有普通对话上方可以启动新的预设流程会话，使用当前输入框的目标与附件；该入口不会自动复制旧对话或所有运行上下文，所需材料应明确提供。展开介绍不会创建 Study 或调用模型。

实际任务简报、材料路径、输出和额外专家由主理人按课题补全。逐篇论文深读可并行；预设骨架不是所有专家顺序穷举。旧 `team/design/diagnosis/review` 研究继续使用已有计划，新界面不再提供三个会诊。

自动判断保持 Study 的 `mode=team`，具体路径存于每版计划，不能仅按关键词机械触发或默认选择综述。交付确认、前端状态和导出按当前计划的真实路径计算：W4 的 `orx research package` 请求 G3，其他流程请求 G4。批准和导出均重新核验完整产物，方案变动或计划版本变更使旧批准失效。前端按具体流程显示确认状态和下载入口。

## 验证范围

回归测试覆盖四套预设的角色与依赖校验、实验边界、流程持久化、每轮上下文注入、W4 的 G3 方案确认和产物变更拦截，以及入口选择和流程预览。真实模型能否完成指定课题仍需提供实际论文、数据和资源进行端到端验收。

## 对话模式边界

对话创建后模式固定。已有“工作模式”对话不会原地切换为专家团；输入框上方入口明确标为“新建专家团对话”，在同一项目下新建独立会话，原对话和历史行为不变。新对话可以使用当前输入框的目标与附件，但不自动复制原对话完整历史或运行上下文。
