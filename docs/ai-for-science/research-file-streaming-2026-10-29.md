# 研究产物与交付日志的流式校验（2026-10-29）

本批基于 `2746fea`，处理研究文件读取的容量及并发变化边界。
原产物入口已有 32 MiB 元数据检查，但随后整份读入 Vec；
交付日志虽然流式 hash，却一直追读到 EOF，没有限制为打开时的长度或复核来源变化。

## 行为与兼容

- `research/files.rs` 从已有证据登记实现提取 FileSource，保存打开的文件、
  文件身份、初始长度和修改时间。它只用于研究产物及日志，不是通用文件框架。
- 每次读取最多初始长度加 1 字节，避免持续追加导致扫描不断追赶。
  全文 hash 使用固定 64 KiB 缓冲，并核对实际字节数、最终元数据及路径身份。
  追加、截断、可观测的重写或替换均拒绝，要求稳定后重新校验。
- `inspect_artifact` 返回既有 Artifact 元数据，不再为 hash 保留整份内容。
  继承、绑定时的依赖／基线检查、自动与显式验收、交付核验、缺失产物提示均接入。
  单个产物仍限制为 32 MiB，恰好达到上限仍可接受；空产物验收仍拒绝。
- 交付日志和证据登记共用来源快照。完整字节 SHA-256、证据摘录、研究包 scope、
  基线、审批 hash 与数据库字段不变；没有改成抽样校验或缓存已批准结果。
- 超限或读取失败只报告错误，已有任务、文件、声明和审批历史不被清理。

## 回归与保留边界

新增回归覆盖二进制、空文件、64 KiB 缓冲边界、32 MiB 产物边界及尾部变化，
快照后追加／截断／同长度重写／路径替换、初始长度加 1 字节上界，
以及部分输出超限时任务不被误验收、交付包保留完整日志 hash 和 scope 结构。
继续运行已有证据并发写入、来源变化、旧产物自动验收及材料输入继承回归。

容量保证是每个文件的流式缓冲和有界读取字节数，不是文件系统的实时超时保证。
完整 hash 仍需 O(文件大小) 的 I/O；某些验收及审批路径仍在写事务内校验文件。
文件身份和元数据检查不能防御同一 OS 账号的恶意并发写入，也不将多个文件变成
同一时刻的原子快照。无法取得必要元数据时明确失败。

研究聚合 JSON 的历史总量、历史 Run 引用策略和日志回收仍单独保留；
本批没有增加任意总量限制、拆表、删除文件、调用真实模型或改变部署。
