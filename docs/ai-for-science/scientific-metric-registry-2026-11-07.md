# 科学指标持久登记（2026-11-07）

这是 `.5` 之后的后续源码候选，推进最初计划中的指标来源持久化；不改写 `.5` 标签或其已发布资产。既有 `metrics inspect` 仍只做当前文件核验，新命令要求显式写入：

```sh
orx metrics register RUN_ID --file results/metrics.json --project PROJECT_ID
orx metrics list RUN_ID --project PROJECT_ID --limit 20 --after 0
orx metrics show EVIDENCE_ID --project PROJECT_ID
```

Agent 会话沿用真实项目归属，省略 `--project` 时从会话解析；显式跨项目、未知会话或跨项目登记均拒绝。列表只查本项目，因此其他项目同名 Run 返回空列表，show 对缺失和其他项目 ID 使用相同错误。计划模式只放行 inspect/list/show，register 保持写入门禁。没有 HTTP/UI、账号服务、Trackio 或网络调用，不启动实验。

## 保存的事实和限制

每次成功 register 新增 UUID 和递增序号，保存完整核验结果：报告内容、原报告 SHA-256/字节数、报告产物路径、Run/实验、commit、冻结代码 SHA/字节数、显式数据文件身份及完整指标序列、固定资源字段和命令。登记时间与核验时间分别保留，并记录生产者版本和序列化核验快照的 SHA-256。快照摘要不是原报告摘要，也不是签名。摘要输入为数据库实际保存的序列化 UTF-8 字节；show 按这些原始字节核验，终端格式化文本另行呈现。

关联仍是报告生产者声明；历史数据只证明登记时核验的字节身份。它不证明运行时实际使用输入、科学正确性、可复现性或理解完成。没有复制原始 JSON 字节、代码归档或数据文件，也不延长这些文件的生命周期；因此 show 不承诺当前文件还在或仍匹配。原始文件改写、丢失或 Run 被清理后，历史登记仍可按 ID 读取；需要核验当前文件时重新 inspect/register，不能通过 show 宣称当前有效。

显式重复登记追加新记录，绝不覆盖旧序列或自动折叠为“最新正确值”。后续声明、审批、交付应引用固定登记 ID 和快照摘要，不能用当前 Run 最新值替换历史来源；该绑定本批尚未实现。

## 事务、预算与生命周期

继续复用 inspect 的严格报告契约及来源预算：2 MiB 报告、最多 64 个序列/10000 点，最多 64 个数据文件/64 MiB，512 MiB 代码归档；读取报告另有流式 2 MiB+1 截断，防止读取期间增长绕过元数据预算。任何输入不符整体失败，不保存部分序列。

序列化快照最多 4 MiB。文件读取、哈希、检查以及快照序列化/摘要在数据库写事务之前完成；短 immediate 事务内复核 Run 的项目、实验、成功状态/退出码、命令、代码/后端身份及时间，再执行单次插入。来源文件此后仍可能变化，语义是历史观察，不是文件冻结或数据库与文件系统的原子快照。失败插入整体回滚，没有残留空记录。

表只允许追加。SQL 触发器拒绝 UPDATE、单独 DELETE，以及 ID/序号冲突的 INSERT OR REPLACE；普通 Run 删除不级联。项目整体删除沿用现有明确生命周期，级联移除本项目登记，禁止据此宣称永久审计存储。没有单项删除入口或自动回收。总配额和归档封存策略仍待后续实现。

list 使用项目/Run/sequence 索引和 seek 游标，默认 20、最多 50 条摘要，只返回 ID、序号、时间、版本和摘要，避免聚合整页完整曲线。nextAfter 仅在确有下一条时返回；并发追加可能在下一页可见，不宣称固定批次快照。show 一次读取一项快照并核对摘要。`storage usage` 增加登记数和快照 JSON 逻辑字节统计，属于共享 SQLite 的逻辑明细，不能再与数据库文件占用相加。
