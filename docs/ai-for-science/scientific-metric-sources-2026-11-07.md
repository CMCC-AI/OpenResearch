# 科学指标来源第一阶段（2026-11-07）

原计划要求 loss/accuracy 等科学指标关联真实 Run、代码及数据版本、命令和资源，并与 token/时长用量分离。本批提供只读文件检查基础；持久登记、运行时输入证明、科研声明绑定、网页曲线、跨 Run 比较、案例/交付封存及 Trackio adapter 仍是后续工作，不把本批视为整项闭合。

## 使用

将指标 JSON 和数据文件放入该 Run 所属项目的产物目录，然后运行：

```sh
orx metrics inspect RUN_ID --file results/metrics.json --project PROJECT_ID
```

Agent 会话中可省略 `--project`，由真实会话归属解析；显式项目不一致或 Run 属于其他项目时拒绝。命令不启动实验、解析器或 Trackio 服务，不访问网络，也不写入指标登记或阅读回执。计划模式仅放行 `metrics inspect`，未来其他子命令默认仍受门禁约束。

报告契约如下；示例中的身份必须替换为该 Run 实际记录的完整值，数值仅为合成示例：

```json
{
  "schemaVersion": 1,
  "runId": "RUN_ID",
  "experimentId": "EXPERIMENT_ID",
  "commitSha": "完整 Git 提交 SHA",
  "sourceSha256": "冻结代码归档的 SHA-256",
  "data": {
    "kind": "artifacts",
    "files": [
      {"path": "datasets/validation.csv", "sha256": "数据字节 SHA-256", "bytes": 4}
    ]
  },
  "series": [
    {
      "name": "accuracy",
      "unit": "1",
      "split": "validation",
      "points": [{"step": 0, "value": 0.8}, {"step": 1, "value": 0.9}]
    }
  ]
}
```

确实没有文件输入的解析计算可显式使用 `"data":{"kind":"none"}`；缺少 data 不等于已声明无输入。单位 `1` 表示无量纲，不自动把百分数和比例互转。名称和数据划分相同的重复序列，即使单位不同也拒绝；训练集和验证集分别保留。step 必须是严格递增的非负安全整数，不排序、不补点、不去重、不降采样或返回部分数据。

## 核验与含义

只接受本项目、成功结束且 `exitCode=0` 的 Run。报告中的 Run/实验/commit/代码归档 SHA 必须逐项匹配已有记录。读取既有冻结归档，核对真实长度和 SHA；迁移后仅允许沿用启动器已有的内容地址目录回退，不能用当前工作树冒充旧源代码。报告文件和数据文件仅接受项目产物目录内的相对路径，拒绝越界链接、特殊文件及 Windows 流路径。

报告最多 2 MiB、64 个序列、总计 10000 点；数据最多 64 个文件且总计 64 MiB，冻结代码归档最多 512 MiB。先验证声明预算，再逐项核验实际长度和哈希，读取前后检查文件身份，并复查 Run 的来源及状态；没有硬执行时间上限承诺。旧 Run 缺少代码身份或任何来源超限/缺失/变化时，整个检查失败并以非零退出，不生成可信零值。

输出包括完整序列、报告 SHA/字节数、核验时间、Run 命令及固定资源字段；不输出完整 backend_json、SSH 主机或凭据。所有结果明确包含含义：这是报告生产者声明的关联及检查时字节身份，不证明程序在运行时实际消费了这些数据，不证明科学正确性，也不等于持久证据。失败 Run 的调试观测本批不纳入科学结果入口，原始日志仍按既有能力访问。
