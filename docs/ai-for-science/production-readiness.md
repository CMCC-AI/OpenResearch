# 生产评估与改进清单

2026-09-21更新：新增[邀请制多用户平台](multi-user-platform.md)，通过独立控制面与每空间专属执行器实现角色与访问隔离，并完成 DeepLiterature 统一登录。下面保留2026-09-20基线；原本地API仍是单用户边界。VM隔离、计费与生产恢复未完成，不能视为全部P0已关闭。

基于 2026-09-20 的代码审查。结论：适合在受信任单用户环境继续试用；不能以当前状态交付公网多租户科研平台。下面是已发现的问题，不是声称完成了渗透测试或容量测试。

## 本轮已修补

- 文献工作区只有前18篇：接入上游分页契约，增加总量和上一页/下一页，搜索/切换标签重置页码。
- 单字查询静默无效：允许单字及空查询，后端以字符数限制500，分页offset限制10000。
- 断连无法恢复：加入明确重试和连接错误状态；终端用户不再看到环境变量或内部请求 URL。
- 上游资源无边界：Deep Literature 响应限4 MiB，并发限4，关闭重定向，保留超时，校验返回数量。
- OpenAlex 缺少 key 支持：服务端 Bearer key、20秒超时，page cap 从200调整为当前官方100。
- 联合发现传 recent 而排序函数只识别 recency：统一参数，加入查询长度边界。
- “加入研究项目”误导：改成“从此论文创建项目”，如实说明尚不能附加到已有项目。

## 建议部署形态

第一阶段：单用户本地科研执行器 + 独立文献服务。默认 loopback，只通过安全隧道访问，单机 SQLite 保留，避免为迁移而迁移。

第二阶段：身份/API控制平面 + 公共文献服务 + 每租户独立科研执行器。租户控制面用PostgreSQL；科研执行器仍可使用本地SQLite作运行状态存储，通过授权事件回传。公网网关不能把所有租户转发到同一个无租户本地API。

第三阶段：任务队列与资源调度、对象存储、分布式配额、证据索引、成本账本和审计。API服务与长任务分离；实验失败、Agent失败、来源不可用分别建模。

## 建设顺序与完成标准

1. 生产底座：身份、隔离、secret、收费开关、备份。完成越权/恶意执行/恢复/预算硬停四项演练才允许团队试用。
2. 研究闭环：多篇项目文献、证据引用、全文检索和双向导航。用户能从一篇证据定位到原文版本，再定位到使用它的实验与报告。
3. 规模化：分布式队列/配额、缓存、服务指标和灾难恢复。设定并实测并发用户与任务数，不能用本地18篇展示当容量结论。

建议初始目标（非已测结果）：RPO≤24小时、RTO≤4小时；文献API可用性99.5%；建立端到端延迟和失败率基线后再承诺P95。对医疗等高风险科研结论另设专业审核流程。
