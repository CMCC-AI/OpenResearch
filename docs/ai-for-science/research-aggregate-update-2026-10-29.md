# 研究聚合更新的序列化成本（2026-10-29）

后续：[活跃研究部分索引](research-active-index-2026-10-29.md) 已减少巡检对结束研究的读取，
并记录索引带来的写入成本；下文为聚合变更检测这批提交的测量与边界。

本批基于 `f656126`。聚合没有总量边界，但直接加上限可能阻断旧研究的查看、
验收和结束；本批先测量并减少现有更新成本，不拆表、不截断历史、不设置任意硬上限。

## 测量与选择

原 `research_update_in_tx` 在同一个写事务内，将完整 Study 序列化为 before Vec，
再次序列化作比较，实际变化后再更新时间并第三次序列化写库。
历史声明和审批 scope 会重复经过 JSON 编码，即使内容没有变化也要完整编码两次。

新增可手动运行的隔离基准：分别使用 64／512 个各 16 KiB 的 inference 声明，
在临时 Store 上交替执行无变化更新和单字段实际更新，各 5 次并取中位数。
下表为同一工作区开发构建下，原实现加相同夹具与本批实现的结果，单位 ms：

| 聚合序列化字节 | 原无变化更新 | 本批无变化更新 | 原实际更新 | 本批实际更新 |
| --- | ---: | ---: | ---: | ---: |
| 1,061,924 | 33.585 | 2.593 | 49.078 | 18.887 |
| 8,494,208 | 275.725 | 21.720 | 400.977 | 149.002 |

这是无并发争用的合成样本，包含 SQLite 读取／解析与必要写入；不使用真实用户数据库。
没有测量 RSS 或线上 p95，不据此承诺生产延迟，基准不作为 CI 的时间阈值。

## 实现与兼容

- 对已解析的 Study 做一次 Clone 快照，以结构比较识别变化，不再建立完整的
  before／after JSON 字节数组。实际写入之前显式释放快照，再更新时间并序列化一次。
- 对 RunContract.options 的开放 JSON 子树补充编码一致性检查：数字保留浮点位表示，
  数组和对象保留序列／键顺序，避免 Value 的 `-0.0 == 0.0` 让编码变化被吞掉。
  该检查只用于聚合变更检测，没有改变既有运行授权的 RunContract 比较规则。
- 未变化时不 UPDATE、不刷新 updated_at，也不规范化或丢弃原始旧 JSON 中的未知字段／空白。
  真实修改沿用已有规范化序列化行为；闭包失败仍由原事务回滚。
- 不改变数据库结构、对外 JSON、审批范围 hash 或研究生命周期；领域类型的 PartialEq
  随结构字段派生，新增字段也参与普通变更比较。

## 回归与保留边界

数据库触发器验证旧 JSON 无变化时零写入、原文及时间戳不变，错误修改不落盘，
实际变化只写一次；另覆盖直接及嵌套的负零／正零、整数／浮点表示变化。
现有交付、材料继承、证据、结束研究等回归继续验证真实调用链。

聚合仍须完整读取、解析和保存，Clone 也仍随内容线性增长；没有获得常量内存保证。
历史总量、active 巡检范围及日志引用／回收策略仍需独立治理，不把此项优化标记为全部容量问题已解决。

复现基准：

```sh
cargo test --locked --bin orx research_aggregate_update_benchmark -- --ignored --nocapture
```

基准默认忽略，已在本批修改前后分别单独执行；功能回归不忽略。
短期基准日志为 `/tmp/orx-aggregate-before.log`、`/tmp/orx-aggregate-after.log`。
