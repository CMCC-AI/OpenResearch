# 性能治理第三批：事件驱动写入（2026-10-23）

基线 `5887756`。本批仅迁移 OpenCode V1 普通消息事件触发的聊天写入；功能扩展及服务器部署继续暂缓。

## 实施

- `src/local/harness/opencode.rs` 的事件处理器只更新消息并返回是否需要 flush，由异步事件循环等待 `maybe_flush_async`，不在同步事件处理器中直接打开 SQLite。仅本会话及已登记子会话的有效正文/工具更新触发该路径，外部事件与未知事件不触发额外 flush。
- `src/local/chat/mod.rs` 将第二批周期检查点的后台写入提取为共用异步 flush。仍使用全局 8 并发执行池，保留 75 ms 广播节奏、约 1 秒存储间隔、工具状态变化触发规则、提示卡存在时落盘、提示卡回执合并与事务内终态保护。
- 广播期间无需落盘时直接广播，不排入存储池、不打开 Store；失败不确认快照，后续周期检查点可以重试。单个 turn 逐次等待写入后才消费下一事件，不建立无界快照队列。
- 最终强制 flush 仍沿用原逻辑，不改最终消息及分支顺序。每次事件内原先可能重复调用的节流 flush 合并为一次，保留完整事件处理后的消息状态。

## 合成慢存储基线

运行 `cargo test --locked event_storage_contention_benchmark -- --ignored --nocapture`。macOS 本地 debug 测试、单线程 Tokio 运行时；16 个合成会话各有独立临时 SQLite，助手正文各 65536 字节，存储工厂额外阻塞 20 ms 后真实打开数据库并写入。旧同步路径与新有界异步路径均使用实际 flush 方法。初始化在计时前完成，每个写入结束后核对正文长度及分支父节点。

| 指标 | 同步路径 | 有界异步路径 |
| --- | ---: | ---: |
| 16 个写入的批次总耗时 | 527.159 ms | 77.245 ms |
| 从批次起点到完成的 p50 | 263.016 ms | 46.049 ms |
| 从批次起点到完成的 p95 / p99 | 526.918 ms | 77.233 ms |
| 5 ms 心跳调度迟到 p50 | 262.211 ms | 2.266 ms |
| 心跳迟到 p95 | 497.211 ms | 2.760 ms |
| 心跳迟到 p99 | 517.211 ms | 2.760 ms |
| 同时执行存储打开阶段的峰值 | 1 | 8 |

完成延迟包括调度和执行池等待，不是单条 SQL 延迟；16 个样本的 p95/p99 都落在最大值，不能用作稳定的生产分位数。心跳按固定 5 ms 截止点统计迟到，阻塞期间错过的截止点也计入，样本数分别为 105、15。仅运行一次、旧路径先运行，存在缓存和执行顺序影响；不设置机器相关性能阈值。

该基准用于验证慢存储不占住异步线程，以及并发打开受约束；独立数据库并不模拟产品共享 SQLite 的写锁竞争，也未测量 CPU、RSS、网络或模型响应。不能将上述比值宣称为生产吞吐或产品整体提速。基准默认忽略，必须显式运行。
