# 性能治理第八批：上下文用量与收尾队列刷新（2026-10-23）

基线 `9ba5259`。本批继续隔离共享 turn 收尾中的同步存储，功能扩展与服务器部署暂缓。

## 实施范围

- 最终消息之后的上下文用量序列化和 Store 写入改用现有 8 并发执行池，外层等待保存完成再进入会话收尾；无用量或没有完成时间时不打开 Store。
- 生产路径使用新的条件 UPDATE：会话 active_leaf、消息 ID、创建时间和完成时间必须匹配，并核对 turn 身份、状态和恢复关联。新分支、停止、同 ID 重试或已恢复 turn 的迟到用量会被跳过，不覆盖当前数据；用量保存仍不改变会话 updated_at。
- 原无条件用量 setter 仅留作测试夹具使用，生产收尾统一走上述版本检查。检查与 UPDATE 在同一 SQL 语句内完成，不拆成异步读后写。
- `finish_turn` 的持久化队列刷新整体移入后台：获取 queue_persistence 锁、读库、过滤派发中消息、解析并替换内存队列、更新派发抑制状态及广播，均保留在原临界区。其他同步调用者复用同一逻辑，没有第二套队列恢复实现。
- 新增 await 位于 turns 异步锁之外；刷新完成后仍核对当前 Active 消息 ID 或 Cancelling 状态，再决定保留 Draining 或释放槽位。没有拆分持久化锁、提前释放槽位或改变派发规则。

取消等待不能停止已经运行的 blocking 任务。上下文写入依靠数据库版本条件防止迟到覆盖；队列刷新仍在持久化锁内读取执行时的当前数据，与并发入队串行，不应用提前缓存的数据库快照。

## 验证

新增四项回归覆盖：

1. 无用量/未完成消息不打开存储，打开失败可显式重试；当前最终消息的用量正常保存且不改变会话排序时间。
2. 模拟慢打开时由异步计时器推进新分支、停止消息、仅停止 turn 状态、重试复用 ID 及恢复关联五种变化，迟到用量均不覆盖已有值。
3. 慢队列刷新期间异步心跳仍运行；派发中项不重新放回内存队列，取消标记存在时不打开存储，原缓存保持不变。
4. 队列刷新持锁期间另一个后台任务尝试入队，释放刷新后两项消息在内存与数据库均保留且顺序一致。

最终验证通过：补强 turn 状态/恢复关联检查后的针对性测试为 19 项通过、2 项专用基准忽略；`cargo fmt --all --check`、`cargo clippy --locked --all-targets -- -D warnings`、`git diff --check` 通过；完整 `cargo test --locked` 退出 0，1217 项单元测试、18 项集成测试通过，8 项专用测试默认忽略。本轮未显式复跑这些忽略项，不将其计作已运行的性能或故障证据。

日志保存在忽略目录 `.mobilesci-run/backport-v0.2.20/acceptance/performance-cleanup-*.log`，最终候选以 `tests-final`、`clippy-final`、`full-tests-final` 为准；无 final 后缀的记录来自补强前版本。源码及日志哈希见 `performance-cleanup-evidence.json`，不提交测试数据库或模型会话日志。

## 仍需处理

- `finish_turn` 的会话 touch、spawn 完成标记、会话快照读取及持有 turns 锁时的 durable lease 释放仍同步执行；需要分别保留归属和令牌条件再迁移，不能机械搬走整个收尾函数。
- 其他队列读写入口、turn 启动、目标事件文件处理、中断清理及部分 harness 路径仍有同步存储，TD-05 不整体关闭。
- 本批没有为上下文用量新增自动重试保证；条件不匹配时保留当前用量，故障时仍沿用 best effort。最终消息失败重试、磁盘满及状态/消息原子性边界保持独立排期。
- 测试证明调度可前进、队列互斥和消息版本边界，未新增吞吐、CPU/RSS 或尾延迟基准，不宣称具体提速比例。

未改 UI、依赖或平台服务，未重启既有实例或部署服务器，未声称生产压力或完整跨平台 CI 通过。
