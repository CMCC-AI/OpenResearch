## 已实施行为

`orx inputs` 显式选择已封存材料的 package/SRC，或本项目成功结束且 exitCode=0 的 Run 所关联的项目产物。材料核验包归属、ready、唯一 SRC、原相对路径、大小及 SHA；产物核验操作者提供的当前字节身份和成功 Run 的状态/代码/命令/后端身份。产物目录复用现有 files/旧 artifacts 的同一 Store 绑定迁移，避免另起一套路径回退。项目产物目录本身不证明文件由该 Run 产生，清单明确标注这种关联是操作者选择，未冒充生产事实。

每次冻结生成新的 UUID 和不可改写清单，保存原件实际字节、原来源标识、目标相对路径、摘要、准备时间和工具声明版本。Run 命令及后端仅存摘要，避免复制可能含敏感参数的原文。记录与查询不运行实验，不生成材料阅读回执、指标登记或审批。`copiesVerified` 是冻结/verify 时的字节观察，`executionObserved` 明确为 false；show 只显示登记历史，不能证明当前文件仍完好。

同一集合的相同摘要原件只存一份 blob，多个目标路径仍逐项保留并校验来源；不同集合各自保存副本，不声称跨集合去重。清单至多 64 个目标、逻辑总量 64 MiB、序列化清单 128 KiB，超限整批失败，不截断。目标名检查相对路径、常见 Windows 非法字符/设备名、大小写及文件/目录前缀冲突；原件路径保留登记值，不把目标命名限制强加给 Linux 原件。目标执行系统的其他 Unicode/平台别名仍须在后续投递阶段检验。

## 使用

先由操作者显式配置独立副本池限额；以下 1 GiB 只是示例，不是系统默认值。该设置属于当前执行器所有项目共同使用的冻结输入池，不能附带 --project，也不能由 Agent 设置。

```sh
orx inputs quota --bytes 1073741824
orx inputs quota
orx inputs --project PROJECT_ID freeze --file selected-inputs.json
orx inputs --project PROJECT_ID list --after 0 --limit 50
orx inputs --project PROJECT_ID show INPUT_SET_ID
orx inputs --project PROJECT_ID verify INPUT_SET_ID
```

`selected-inputs.json` 示例：

```json
{
  "schemaVersion": 1,
  "files": [
    {
      "path": "datasets/training.csv",
      "source": {
        "kind": "material",
        "packageId": "11111111-1111-4111-8111-111111111111",
        "sourceId": "SRC-0001"
      }
    }
  ]
}
```

产物选择改用 `source: {"kind":"artifact","runId":"RUN_ID","path":"results/data.csv","sha256":"完整小写 SHA-256","bytes":123}`。路径在该项目现有 files 根内，不能指定任意主机文件或 URL。没有自动选择最新数据或从工作树补齐的回退。

**保留约束：本版本冻结集合永久保留，尚无已冻结集合删除入口；含冻结集合或在途预约的项目禁止删除。** 删除流程的数据库事务和文件夹回滚规则继续适用；不留下删除了 Run/会话却保留半个项目的状态。CLI help 和清单也说明此限制，不能把本批视为材料/Run 生命周期治理已完成。

## 容量、事务和中断

- `input_set_budget` 显式配置正的 JSON 安全整数字节数；没有任意默认限额，未配置时不接受冻结。`frozen_input_sets` 保存 preparing→copying→frozen/cancelled 的单向状态及不可变清单/摘要。
- 短 immediate 事务在复制前预约清单加集合内唯一 blob 的精确逻辑字节数；所有项目的 frozen、preparing/copying 一起计入准入，两个并发连接不能超额，降低配额不能低于现占用。取消历史不参与活动预约索引扫描。
- 文件读取、复制、完整 SHA、同步和回读均在写事务外。提交还重新检查至多 64 个 blob 的名单与类型，未知项立即拒绝，不先收集无界目录。提交前复核项目根、关联 Run、材料清单、原件及副本文件身份。SQLite 短事务中只做身份/状态复核，不重读正文。Unix 另同步目录；不把这解释为所有宿主文件系统/硬件断电的通用保证。
- 本池计数是服务管理的副本/文件清单逻辑预约，quota 输出明确 countsDatabaseMetadata=false；取消后保留的清单 JSON 仅计入项目元数据观测，尚未受本池准入上限约束，必须纳入后续全局容量治理以防长期增长。计数不包括材料池、源代码 tar、日志、ZIP、数据库/锁文件元数据或外部直接写入；不等于物理磁盘用量或整个工作区总配额。`orx storage usage` 新增当前项目的台账统计，注明 ledgerOnly；未知/额外文件在 verify 或恢复时明确拒绝并保留。
- 每个预约持有独立文件租约，进程中断后预约仍计占用，不按时间猜测自动释放。正常失败仅在确认清理自己分配的未提交路径后取消预约；无法确认或无法清理时保留台账与容量。frozen 身份不可 UPDATE、DELETE 或 INSERT OR REPLACE；项目删除也不能绕过保留。

恢复只针对未提交预约，默认预览；明确 --apply 才会清理。Agent 不能调用配额或恢复（包括预览）。活跃租约、未知文件、链接、归属尚未确认的已有目录和已冻结集合均拒绝删除。

```sh
orx inputs --project PROJECT_ID recover INPUT_SET_ID
orx inputs --project PROJECT_ID recover INPUT_SET_ID --apply
```

目录不存在但预约存在时，空闲租约下可显式取消；目录创建归属尚未确认时保留供人工检查。冻结集合缺失/损坏不会自动释放其容量或改写历史，verify 明确失败。进程间操作不是可防同 UID 恶意篡改的文件系统事务，消费前仍须核验副本。

## 权限与验证范围

Agent 命令继承当前会话项目，显式跨项目拒绝。计划模式只允许 list/show/verify 及纯 help；使用真实 Clap 解析，不能把 --project 的值伪装成只读子命令以放行 freeze。重定向继续拒绝。数据清单只接受封闭 schema，不含可执行命令，材料内容不升级成系统指令。Unix 副本池根目录的权限位设为 0700；Windows 沿用账户数据目录的权限边界，不声称通用 ACL 或对同 UID 的强隔离。共享文件核验先拒绝非普通文件；Unix 采用非阻塞打开，使原路径/链接被替换成 FIFO 时的身份探测不会阻塞。验证命令不创建缺失的池目录或隐式释放保留。

定向存储回归覆盖原件改变/删除后的独立副本、别名去重、归属/ready/SRC、冻结保护、校验损坏/额外文件、原件/清单/副本/Run 提交前变化、超限、同池并发预约、写锁外实际复制、活跃租约、未知文件、目录归属未定和显式恢复。真实子进程在完成实际副本后、登记 frozen 前被终止；剩余预约保持计费，恢复只移除该未提交集合，旧冻结集合仍能核验。该测试是进程中断测试，不是断电或实际科研实验。

两项真实 CLI 回归覆盖 operator 配额→freeze/list/show/verify、原件改变后的历史副本、损坏拒绝及 Agent/跨项目边界；审计 runs/messages/queue/spawns/阅读事件/科学指标登记均为零。完整本地八线程回归通过 1509 项单元及 35 项普通 CLI，13 项单元与 1 项外部 PDF 忽略不计通过。随后仅加强既有台账防覆盖断言，并明确 quota 输出不计数据库元数据；最终源码的 18 项冻结定向回归通过，全目标 Clippy 零警告，4 项版本/发行台账测试与格式检查通过。远端模拟合并 CI 仍须本候选自己的证据，不借用 PR #15 或已发行 .6。
