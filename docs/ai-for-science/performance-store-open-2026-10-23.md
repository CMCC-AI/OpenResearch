# 性能治理第五批：Store 打开兼容性开销（2026-10-23）

基线 `dc7a66b`。只优化已经识别的打开热点，功能扩展和服务器部署继续暂缓。

后续进展：共享 turn 收尾的最终消息已接入有界后台存储，并增加终态竞争保护，见[第六批记录](performance-final-flush-2026-10-23.md)。状态转换、用量结算及最终失败重试边界仍保留。

## 诊断与改动

`Store::open` 每次执行权限模式兼容性 UPDATE 和偏好行 INSERT，即使所有行已是当前格式。SQLite 的无匹配 UPDATE 仍可能需要写入权限；反复按 harness 扫描会随会话数量增加 CPU 开销。分阶段测量确认，在本轮合成样本中兼容性阶段约占打开阶段总耗时的 72%。

将原有转换语句原样提取到 `normalize_permission_modes`，先读取当前数据库：仅在缺少 UI 偏好行、会话权限为空/过期、或偏好权限需要转换时继续执行原有转换。保留 Claude Plan、Codex/OpenCode Plan 标记、旧值映射、未知 harness、NULL 偏好和 reasoning level 的原有语义。

此检查每次打开均执行，不缓存“已迁移”状态；较旧写入方或导入在首次初始化后引入旧值，下一次打开仍能识别。未改连接生命周期、data-dir 解析、迁移标记、超时、SQLite 清理或执行池容量，不建立跨数据库的全局缓存。整个 Store 打开仍可能写入；“无需写锁”仅指数据已规范时的权限转换阶段。

`open_profiled` 为内部泛型观察入口，将连接设置、建表/索引检查、列迁移检查、清理、兼容性及 research/spawn 初始化分段。普通打开传入空观察函数，不读取时钟、不输出测量日志；显式测试传入观察回调，不暴露新产品接口。

## 合成测量

命令：`cargo test --locked store_open_profile_benchmark -- --ignored --nocapture`。本地 macOS debug 测试，在临时 SQLite 中预置 1000 个已规范的 OpenCode 会话，连续打开 30 次，逐次核对数据库行数。初始化及行数校验不在分段计时内；包含热缓存和观察回调开销。优化前后在相同测试条件下分别执行一次。

| 阶段（30 次累计） | 优化前 | 优化后 |
| --- | ---: | ---: |
| 连接及配置 | 15.409 ms | 15.067 ms |
| 表/索引检查 | 4.705 ms | 4.984 ms |
| 列迁移检查 | 1.291 ms | 1.320 ms |
| 清理 | 0.683 ms | 0.688 ms |
| 兼容性（含权限转换检查） | 59.320 ms | 8.312 ms |
| research/spawn 初始化 | 1.367 ms | 1.284 ms |
| 分段总计 | 82.775 ms | 31.655 ms |

按该样本，平均每次打开的分段总计约 2.76→1.06 ms，降低约 62%。这不是完整接口延迟、冷启动或生产吞吐测量；未做随机交替或大样本显著性分析，不将该比值外推到所有数据量和部署。

## 验证

- 干净数据库的权限转换：另一连接持有真实 `BEGIN IMMEDIATE`，当前连接 busy timeout 为 0；转换仍成功，证明该分支不需要写锁。
- 暖打开后新写入旧的 OpenCode Plan 和 Claude 偏好 Plan，下一次打开仍正确转换；Plan 标记、reasoning level 保留，NULL 偏好不被误改。
- 原有权限/Plan 映射、偏好行播种、旧 schema、侧聊迁移及数据目录生命周期随完整 Rust 回归继续验证。

最终验证：`cargo fmt --all --check`、`cargo clippy --locked --all-targets -- -D warnings`、`git diff --check` 通过；完整 `cargo test --locked` 退出 0，1207 项单元测试、18 项集成测试通过，8 项专用测试默认忽略。分阶段基准及共享数据库基准均另行显式执行通过。

共享 SQLite 复测三轮，每轮 16 个会话、64 KiB 正文、20 ms 注入打开延迟，异步批次分别 91.956、95.875、63.131 ms，心跳迟到 p95 分别 5.263、2.684、2.701 ms，打开阶段峰值均为 8；同步对照为 549.178、570.060、579.294 ms。48 次异步与 48 次同步写入均无错误，消息长度和父节点核验通过。这些波动不能用来证明相较第四批端到端吞吐继续提升；本批量化收益限于上述无延迟打开 profile，复测用于确认并发正确性和调度响应未丢失。

日志保存在忽略目录 `.mobilesci-run/backport-v0.2.20/acceptance/performance-open-*.log`：`before`/`after` 为分阶段样本，`full-tests` 为完整回归，`clippy` 为静态检查，`shared` 为共享数据库复测。源码和日志哈希见 `performance-open-evidence.json`。基准开发时最初误用有 500 行上限的列表接口校验 1000 行，已改为直接 COUNT 校验；优化前后的正式记录均来自修正后相同夹具，不涉及产品分页行为变化。
