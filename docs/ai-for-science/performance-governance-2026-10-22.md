# 性能治理首批：聊天存储读取（2026-10-22）

本批以 `87abd8e` 为基线，仅优化现有聊天读取路径。功能扩展、研究流程验收及服务器部署暂缓。沿用 v0.2.19 产品基线和现有数据格式，不引入新依赖。

后续进展：OpenCode V1 的周期检查点已实施存储隔离和迟到写保护，见[第二批记录](performance-checkpoints-2026-10-22.md)。事件驱动及最终写入、其他适配器和并发压力基线仍保留，以下首批测量不替代后续性能验证。

## 已实施

| 热点 | 改动 | 影响与边界 |
| --- | --- | --- |
| 会话列表和详情在异步工作线程同步打开、读取 SQLite | `src/commands/up.rs` 复用现有 `blocking_task`，存储段移入最多 8 个并发任务的执行池 | 慢存储不再占用处理该请求的异步工作线程；不保证查询自身变快。取消后的 permit 仍由实际存储任务持有，未改并发约束 |
| 列表逐项在线性集合中判断忙碌状态 | 读取结束后采样活动会话并转为 `HashSet` | 忙碌判断从 O(N×B) 降为期望 O(N+B)，N 为列表长度、B 为活动会话数；不在数据库读取期间持有活动会话锁 |
| 消息接口连续打开两次 Store | 新增内部 `list_messages_with_store`，同一次请求复用一个 Store | 减少一次连接初始化及其幂等维护开销；仍先读消息、后读分支叶子，不改并发更新时的回退语义 |
| 单条工具状态恢复先读整段历史再查找目标 | `src/local/chat/mod.rs` 改用已有按主键查询，并显式核对 session_id | 不再读取其他消息正文；保留事件应用、未完成工具收敛、分支与原生会话元数据、成功后清理文件的行为 |

没有建立长生命周期全局连接缓存，也未改聊天检查点写入顺序。TD-05 仅关闭上述读取热点，不能据此标为全部完成。

## 验证与测量

- 单线程 Tokio 测试让存储工厂等待异步心跳释放，验证同步等待不会阻塞唯一异步工作线程；另覆盖项目范围、全局范围、侧聊排除、归档过滤、游标分页及非法游标。
- 单条恢复测试验证跨会话访问被拒、缺失目标不写入、运行中工具收敛为 interrupted，分支/原生会话标识及时间字段保留。
- 显式运行 `cargo test --locked target_message_lookup_benchmark -- --ignored --nocapture`。macOS 27.0.1、Rust 1.93.1、debug 测试构建，临时 SQLite 中插入 5000 条消息，每条正文 JSON 4135 字节；各执行 20 次旧式全量读取和新式主键查询。

| 合成测量 | 全量读取后定位 | 按消息 ID 查询 |
| --- | ---: | ---: |
| 20 次查询总耗时 | 216.804 ms | 0.275 ms |
| 单次读取的正文 JSON 字节数 | 20,675,000 | 4,135 |

这里只量化已打开连接上的查询，包含热缓存影响；字节数是正文载荷，不是 RSS、磁盘物理读取量或完整响应大小。没有测量网络、Store 初始化、消息恢复写入或端到端延迟，不将此比值宣称为产品整体提速。基准默认忽略，不用机器相关耗时阈值阻断 CI。

最终验证：`cargo fmt --all --check`、`cargo clippy --locked --all-targets -- -D warnings`、`git diff --check` 通过；`cargo test --locked` 为 1195 项单元测试、18 项集成测试通过，5 项专用测试默认忽略；其中本次新增的忽略基准已另行显式运行通过。第一次全量测试受沙箱限制，本地监听端口与进程检查失败后中止；随后获准在允许这些操作的环境完整重跑，退出码为 0，不将首次环境失败计作代码回归通过。

原始日志在忽略目录 `.mobilesci-run/backport-v0.2.20/acceptance/` 的 `performance-*.log`，完整成功回归为 `performance-rust-tests-unrestricted.log`，Clippy 为 `performance-clippy.log`，合成测量为 `performance-benchmark.log`；源码及日志摘要见 `performance-evidence.json`。不提交测试数据库。本批未改 UI、平台服务或依赖，未重新执行全仓跨平台 CI，也未部署或重启现有本地服务。
