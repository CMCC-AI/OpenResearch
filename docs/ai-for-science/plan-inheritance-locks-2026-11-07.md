## 问题与影响

第六版发布后复核发现，`research_set_plan` 在 `research_update` 的 SQLite immediate 写事务中逐个调用 `inspect_artifact`，最多处理 40 个任务、每任务 30 个输出，单文件上限 32 MiB。大量或缓慢文件读取会延长全库写锁，影响同库消息、任务及其他研究更新。交付和科学指标已采用锁外核验，计划继承仍残留这一条路径。

本批将计划修订实现移至 `src/store/research/plans.rs`，分为准备和短事务提交。CLI、HTTP 和 Agent 调用仍走同一公开 `research_set_plan` 方法，无新权限、协议、迁移或 UI 资源变更。本批属于 .6 之后的独立候选，不移动已发行 .6 标签，也不表示生产已更新。

## 实施契约

1. 准备时读取研究文档，检查有效计划、活动任务/派生/Run 与必要审查角色；按相同流程、任务角色/简报/输出/依赖和 forceRerun 筛选候选。真实文件打开、32 MiB 预算及完整 SHA-256 核验都在数据库写事务之外。
2. 记录每个合格输出的原相对名、规范路径、文件身份及元数据。Unix 保存设备号/inode 和修改/变更时间，无需为每个输出一直保留描述符；其他目标使用既有 same-file 身份句柄。1200 个输出的场景在 Unix 子进程中以 128 个描述符上限验收，不能改为少继承来规避耗尽。
3. 提交时持有短 immediate 事务，比较完整研究文档（包括原有开放 JSON 编码区别），重新检查活动、材料分支集合、旧专家材料上下文、证据摘要及审查角色。研究文档发生并发变化时明确拒绝，不能仅按更新时间推断未变或覆盖新状态。
4. 对实际将继承的输出重新解析当前相对路径，检查边界、同一规范目标、文件身份/长度/时间；不重读文件正文或重新哈希。核验后发生文件替换、删除、根定位变化导致规范目标不同或链接改指时拒绝该次计划，不留下新计划、审批或绑定版本。Unix 变更时间同时覆盖同长度写入后恢复 mtime 的情况。
5. 延续原继承规则：准备前已失效、缺失、超限或不安全的产物使该任务及依赖任务回到 pending；摘要变化本身不重做合格任务，显式 forceRerun、流程变化、材料变化、依赖变化或审查证据变化仍阻止相应继承。成功修订仍生成新的 G1 待审批，不自动重用旧批准。

文件快照是乐观的元数据和身份复核，不是文件系统事务或防恶意篡改证明。最后复核之后仍可能被外部进程改写；后续绑定/交付继续执行既有核验。原件、执行环境封存、总配额和其他仍在写锁中读取文件的方法没有因此完成；本批只收敛计划继承路径。短事务仍有有界元数据调用，并非零文件系统操作。

## 当前验证

11 项计划继承回归通过，其中新增 7 项覆盖：

- 独立 SQLite 连接持有写事务时执行实际产物哈希，证明正文核验未持有原连接写锁；无计时阈值或睡眠判断。
- 同时间戳研究修改、新声明、新派生和 Run 转活动时拒绝过时提交，保留并发状态和旧绑定版本。
- 准备后材料分支或旧专家上下文变化时，不继承先前任务；新计划固定新的材料集合。
- 准备后内容变化、同字节/同 mtime 文件替换、删除及项目根变化时拒绝，旧研究文档不变。
- 准备前内容失效、缺失和超限时保留 pending 及依赖传播语义。
- Unix 符号链接改指与同长度写入恢复 mtime 时拒绝。
- Unix 128 描述符子进程中，40×30 个实际文件全部核验并继承，保留强制审稿/引用审计角色和证据摘要。
