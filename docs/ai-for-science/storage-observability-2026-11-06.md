# 项目容量观测与归档保留边界

本批实现 `orx storage --project <project-id> usage`。Agent 会话内可省略项目，沿用实际会话归属；未知会话不能退回手工 project，跨项目覆盖被拒绝。命令读取当前持久数据库的根目录，避免测试或显式数据目录误扫全局路径。

## 可观察项

- 当前项目的 sealed/unsealed 材料包数及存储逻辑字节，按有效清单归属过滤；不会列出其他项目的材料名或路径。无法建立归属的清单单独计数，不作为可删除对象。
- 当前项目文件总量及 delivery-bundles 子集，后者已包含在前者中，不能重复相加。
- 项目研究文档和读取回执的数量及 JSON UTF-8 字节数，提供后续分页/拆分之前的增长基线；记录元数据查询与总观测耗时。
- 执行器共享 SQLite、WAL、SHM 普通文件的逻辑字节。它们不属于单个项目，不能将各项目看到的数据库大小相加。
- 材料配置限额属于整个执行器，项目占用不是执行器剩余额度。本批不计算缺乏完整分母的可用比例。

所有文件数/字节均为逻辑路径占用，不是物理已分配空间，不去重硬链接。查询不读取正文、ZIP 载荷或凭据。SQL 元数据在一个只读事务中取样；文件扫描与写入可以并发，不是业务配额准入快照，不对目录执行迁移或删除。CLI 打开 Store 的正常 schema 初始化仍沿用既有行为。

目录扫描按条目检查预算：最多 100000 次、64 层、3 秒；清单最多读取 4 MiB。权限失败、链接、深度/时间/条目预算耗尽时返回 `complete=false` 及已观察下界，不能将其展示为完整占用。不会跟随静态目录链接或循环；这不是跨进程原子文件系统快照。

## 受保护回收尚未闭合

当前研究的 deliverySnapshot 只描述当前包；历史审批并不保存所有旧 ZIP 的完整映射。`archiveRetention` 因此明确所有缓存归档受保护，`deletionCandidates` 为空。现有未完成材料的显式回收仍只处理 unsealed 且超过保留期的上传，不扩到 sealed 输入或交付 ZIP。

这批提供观测，不宣称历史归档目录已完整登记，也不新增 apply/delete 路径。下一步需持久登记每次交付准备/提交/批准的归档身份和引用，兼容旧未知包，保护当前输入、来源/声明、历史审批、活动 Run、在途准备与恢复所需数据。只有建立这些关系并验证并发和恢复后，才提供可复核的回收预览及受保护回收。

## 验收

边界测试验证普通文件逻辑字节、遍历预算、Unix 链接循环跳过；真实 CLI 夹具验证项目归属、其他项目材料不可见、中文路径回执 UTF-8 字节、共享/子集口径，以及查询前后事件和历史缓存字节不变。最终测试和跨平台 CI 结果另列执行台账；代码实现、本地通过、发布和部署分别记录。

本地当前已通过：1 项目录/预算/链接边界测试、1 项真实 CLI 项目隔离/UTF-8/归档保留回归和全目标 Clippy 零警告。容量命令仍持有生命周期读锁以阻止目录搬迁，但跳过常规命令的旧缓存自动迁移；夹具验证旧缓存保持原处。测试子进程显式隔离 ORX_CACHE_DIR 和材料限额，避免借用开发者的缓存或环境。基于归档修复后的本地完整单元回归 1450 项通过、13 项既有忽略；合入阅读分支后仍需对最终合并候选执行完整 CI，不将当前结果替代最终发行证据。
