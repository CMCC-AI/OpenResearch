# 日志证据有界读取与短写事务（2026-10-28）

接续提交 `e03386f`，处理 [TD-18](technical-debt-next-priorities-2026-10-28.md) 的日志摘录和 CLI 请求读取容量问题。原来实验声明在 `BEGIN IMMEDIATE` 内完整读取日志并构造全量行数组；最多 201 行不限制单行字节数，CLI 的 256 KiB 限制也在完整读取后才检查。

## 行为与实现

- `src/store/research/evidence.rs` 从研究聚合中独立承接证据登记。先读取研究与终态 Run，随后在写事务外以 64 KiB 缓冲扫描日志，只缓存选中范围；全文 SHA-256 仍包含范围外的所有字节。超长未选中行不需要缓存。
- 行范围继续使用含首尾的 1 起始编号，最多 201 行；保留 lossy UTF-8、CRLF 规范化及末尾换行语义。摘录原始字节与解码后结果分别限制为 64 KiB，避免非法 UTF-8 扩张突破容量约束。
- 声明所有字符串字段的 UTF-8 字节总和限制为 64 KiB。CLI JSON 文件沿用 256 KiB 总上限，但读取最多上限加 1 字节后即拒绝，不先把超大文件载入内存。超限会明确报错，需要缩小声明或日志行范围。
- 捕获阶段保存文件句柄、文件身份、长度、修改时间和 Run 来源快照；读取最多初始文件长度加 1 字节，避免持续追加让扫描无限追赶。读完检查日志稳定性。
- 写事务只重新加载当前研究、核对 active 状态和项目归属、重新核对 Run 的项目/状态/commit/更新时间及日志身份/元数据，然后追加声明。读取期间其他声明和计划更新不会被旧研究快照覆盖。来源变化则拒绝并要求重新登记。
- 团队技能说明同步容量边界。数据库结构、外部字段和完整日志哈希语义不变，已有声明保持可读。

## 回归场景

新增五项 Store 测试及一项 CLI 读取测试，覆盖：

- 单字节分块下的 UTF-8、非法字节、CRLF、空行、无末尾换行、末尾单独 CR，以及旧 `str::lines` 语义一致性。
- 201 行边界、无效范围与 EOF；64 KiB 摘录边界、超长选中行提前拒绝、解码扩张，以及 5 MiB 未选中长行的完整哈希。
- 读取回调期间另一连接以零 busy timeout 成功写入声明，最终同时保留两个声明，证明长读取未占写事务且不会丢失并发更新。
- 捕获后研究停止、Run 来源变化、日志追加或路径替换时拒绝提交；扫描过程中日志变化及容量拒绝不写研究记录。
- 无限输入最多读取 256 KiB 加 1 字节便拒绝，恰好 256 KiB 的合法 JSON 仍可解析。

## 仍需治理的边界

整份日志哈希仍需 O(日志大小) 的读取时间；本批约束内存和写事务持有范围，没有设置日志总大小上限或抽样哈希。提交时仍有短小的文件身份/元数据检查，不能保证慢文件系统下的硬实时写锁期限。

文件身份/元数据检查用于发现普通并发追加、重写或替换，不是恶意本地进程的文件不可变证明。提交后变更仍由交付阶段的全文 hash 校验拒绝。若底层文件系统不能提供修改时间，登记会明确失败。

本批不限制研究聚合的历史声明总量，不改变 SQLite 读取历史聚合 JSON 的方式；这些累计容量问题继续保留。历史 Run 的交付引用策略 TD-17、研究结束入口 TD-16 和 `while_idle` 的低频全局锁 TD-05D 尚未实施。

未改动 UI、部署或重启服务；工作区中并行产生的 UI 源码及构建资产改动由其原有工作保留，不纳入本批提交。
