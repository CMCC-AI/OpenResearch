# OpenCode 原生压缩冷恢复与治理收口（2026-10-25）

基线 `93391c5`。选择性回移官方 [#761](https://github.com/alphaXiv/OpenResearch/pull/761)（`228231a0e29b804a1079151114304e862a670704`）的 OpenCode 后端部分；它属于 v0.2.21 之后的 main 更新。产品仍为 `0.2.21-mobilesci.1`，真实上游祖先仍为 v0.2.19，整体保持 partial 回移，不宣称完整升级或新版本发行。

## 本批完成

- 以前已保存原生 ID 的聊天在服务冷启动后压缩会报“先发消息”；现在先查原生数据库位置，再复用已有启动流程恢复服务，在同一原生会话上执行压缩。隔离库和旧库都保留各自路径，不创建替代会话。
- 所选模型改变时，原来可能退回 transcript 摘要并清除原生 ID；现在按既有模型优先级重建常驻进程，验证标题/压缩辅助模型后执行原生压缩。原生调用失败明确报错，不自动退回摘要。没有原生 ID 的聊天保留原有摘要路径。
- 冷启动前拒绝缺失或非法模型；原生 ID 在数据库中找不到时拒绝恢复，不创建空库代替历史。数据库损坏等读取错误直接传播。
- 项目与原生会话读取使用共享 8 并发后台池，不照搬官方的同步项目读取或无界 lookup worker。复用现有启动锁、进程管理与 Stop 归属检查，不增加调度框架。
- 整个原生压缩（含恢复）最多 300 秒，超时停止该聊天的常驻进程；V2 完成轮询也使用同一上限。现有 Stop 中止原生请求、终态消息与上下文写入保护保持有效。

## 自动化验收范围

新增三项回归，第三项在隔离子进程中分别使用 isolated/legacy 两套合成数据库和临时 Git 仓库。模拟 OpenCode 可执行文件通过真实启动、健康检查和 HTTP 请求接入，不调用模型：

1. 无效模型在启动前拒绝。
2. 缺失原生会话不创建隔离库或旧库。
3. 冷恢复经实际 `ChatHost.compact_session` 落为 completed，原生 ID/bootstrap 保留；同模型复用 PID、切换模型更换 PID，HTTP payload 使用选择的模型；HTTP 500 不吞掉错误，原生历史保留。
4. 在第三项的两套环境中，再阻塞原生压缩响应并调用真实 `interrupt_by_user`；原生 abort 后响应可以返回，但最终进度仍为 error，busy 释放，原生 ID/bootstrap/用量和历史保留。

首次定向运行受沙箱回环监听限制失败，授予本机测试端口权限后回归通过；首次失败不计为功能失败或最终通过证据。日志与候选源码哈希保存在忽略目录 `.mobilesci-run/opencode-cold-compaction/`。

最终验证：完整 `cargo test --locked` 退出 0，**1269 项单元、18 项集成测试通过，11 项专用测试默认忽略**；三项新增定向回归、`cargo fmt --all --check`、Clippy all-targets/-D warnings、`cargo build --locked`、diff 检查、上游基线及两项产品版本回归通过。既有 UI 产物入口预算检查通过（2,949,101 raw / 900,558 gzip bytes）；本批没有改动 UI 源码或产物，不把上一批 420 项 UI 结果记作本轮重新执行。

不把上述模拟服务等同于真实供应商模型验收；300 秒超时分支没有等待满时长的故障注入。未覆盖其他 harness 的冷恢复、完整 #761 能力声明或全部跨平台 CI。
