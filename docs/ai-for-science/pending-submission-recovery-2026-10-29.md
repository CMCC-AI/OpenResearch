# 待确认发送与草稿恢复（2026-10-29）

接续 [steering 持久回执](steering-receipts-2026-10-28.md)，本批从 `7dc3ec6` 实施前端恢复。只恢复已准备发送的待确认请求及其草稿，不将所有尚未发送的编辑区内容改为持久存储。

## 保存与身份边界

- `ui/src/pendingSubmissions.ts` 使用 IndexedDB 保存原 client ID、普通／steering 模式、请求签名、原草稿、File／图片、相对路径、去除 DOM Range 的注释，以及实际传输参数。新会话先取得会话 ID，再在消息 HTTP 请求前等待保存；保存本身不发送消息。
- 记录按浏览器 origin、应用基础路径、已验证账号服务／用户、既有运行时身份、项目及会话隔离。运行时使用现有的 local 标识或 SSH session/database 身份，本批未扩展服务端数据库实例协议。未取得账号身份及只读案例不读写持久恢复记录；普通侧边聊天沿自身会话 ID 使用同一流程。
- 签名中的查询 generation 仅在验证相同持久作用域后，替换为当前查询代次；正文、附件、注释和设置仍需匹配。不能通过刷新生成另一个请求 ID 绕开原投递结果。
- 每个会话保留一个待确认请求。IndexedDB 的读写事务禁止另一 ID 覆盖它；删除也在同一事务中比较 ID，迟到回包不能删除新请求。已有待确认请求但内容／设置不同，发送入口要求先核实或明确放弃本地记录。

## 恢复与用户编辑

进入会话先读取记录、按原 session/client ID 查询服务端回执，不自动重发：

| 结果 | 行为 |
| --- | --- |
| 已登记 | 清除匹配的本地记录并重读会话；只有编辑区仍与原恢复草稿一致、核查期间没有新编辑时才清空它，同时更新 stash 的 live ref，防止切换路由后旧草稿复活。 |
| 未确认／缺少接口／查询失败 | 保留原身份与传输模式；编辑区为空时恢复关联草稿、附件和注释，已有新内容时不覆盖。显示核实、恢复草稿与设置、仅放弃本地记录入口。 |
| 作用域退休／会话删除 | 不把异步结果写入新会话或新账号的编辑区；删除已知会话时清理其记录。 |

后台核查不自动更改用户当前模型设置。用户点击“恢复上次草稿与设置”时才恢复原设置；若编辑区有不同的新内容，要求先保留或清空。仅放弃本地记录不撤回服务端请求，界面明确说明这一点。

同一页面中仍在发送的请求由共享 flight 标记保护，往返路由不会把它当成待重发草稿。保存完成后再次检查原工作区及删除状态，再调用传输。放弃记录期间也持有同一保护，防止删除与新发送交错；恢复／放弃按钮在本地发送期间不可操作。

## 附件和命令重试

重试必须复用首次请求的 `wire.images`、材料包 ID 和实际 `TurnOptions`。只恢复 File 再调用上传会产生新的材料 ID，改变服务端 request hash，因此此处直接使用已登记引用，不重复上传。文件夹相对路径由 attachment name 保留，File 的字节、名称和 lastModified 由 IndexedDB 保存。

`/plan` 等请求恢复后使用已保存的实际传输文本和计划模式，不重新执行本地命令解析／切换。编辑了正文、附件或设置的请求不能冒用旧身份执行。

## 退出及存储故障

退出账号先撤销当前页面对该 owner 的后续写入，再清理该账号的恢复记录，随后执行既有浏览器 logout API。其他账号记录不受影响；晚到的保存不能重新写入已退出的账号。

打开数据库和事务均有有界等待。持久写入不可用时可退回当前页面内存，并明确提示刷新恢复不可用；读失败及记录无效会报告错误，不伪造成功或自动恢复不完整附件。记录不按时间自动失效，正常在已登记、明确拒绝、用户放弃、会话删除或账号退出时清理。

需要与上一批支持 steering 登记／去重的后端配合。旧后端缺少回执时仍保守显示未知，前端存储本身不能补足旧服务端的 native steering 幂等性。本批没有重启当前开发槽、部署服务器或更改已发布版本。
