# 近期性能改造复核与队列失败收敛

基线 `4a845b9`，复核近期发送入口、上下文、用量、元数据及忙队列改造。产品版本保持 `0.2.21-mobilesci.1`，上游整合仍为 partial。

## 复核结论

| 现有改造 | 处理 | 理由与边界 |
| --- | --- | --- |
| 共享 8 并发后台池 | 保留 | 同步 SQLite、文件和 Git 操作需要离开异步调度线程；实际 worker 持有 permit，取消等待不会提前放大并发。没有为每个阶段另建执行池。 |
| TurnGuard、cleanup 锁和 reservation_id | 保留 | 防止取消后占位提前释放、Stop 与持久化交错，以及旧清理误删后继占位；Store 连接继续复用，不拆成新的状态机。 |
| 忙队列设置与消息的单事务、revision 回滚 | 保留 | 解决设置写入成功而入队失败时的内存/数据库分歧，不扩大为跨文件事务。 |
| 派发刷新失败后的占位释放 | 本批修正 | 原释放路径发现缓存队列就再次 drain；持续打开/读取错误可能绕过派发重试预算，形成无等待的任务链。 |
| 无调用的 refresh_persisted_queue 包装 | 删除 | 现有调用已使用持锁或异步版本，避免保留重复入口。 |
| 忙队列全局锁、其余同步入口 | 保留为未解决项 | 搬到后台不等于缩小锁范围。没有先释放锁再写入，也没有仅为消除同步调用而机械扩展 worker 阶段。 |

## 本批修正

派发前刷新暂时关闭当前 TurnGuard 的自动队列交接；成功返回后恢复默认行为。打开连接、读取、后台任务失败，或等待被取消时，guard 仍按原 reservation_id 释放自己的占位，保留缓存和持久队列，不立即递归派发。

后续恢复复用 `orx up` 既有租约巡检（当前间隔为 TTL 60 秒加 1 秒）及队列恢复入口。没有新增定时器、重试表、全局暂停状态或重试预算；读取故障不会被算作模型/消息派发失败，也不会永久加入 suppression。真实派发仍执行原有 next_retry_at、耗尽与显式重试规则。刷新错误写入服务日志；如果巡检本身也因存储故障失败，需要存储恢复后才能继续。

新增回归使用连接私有临时表制造真实 SQL 读取错误，验证释放后 busy=false、缓存和数据库消息均保留，并能在换回正常连接后重新刷新；另验证等待 cleanup 时取消不会立即重新 drain。既有取消、Stop、旧占位拒绝、连接复用及事务失败回归继续运行。
