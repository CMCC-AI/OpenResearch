# 材料声明来源与 CLI 原文定位（2026-11-03，源码实施）

基于 `4a7201f1` 的读取回执，使用独立 worktree 和 `feat/material-claim-provenance` 分支实施。本批完成后端可校验的来源关联与 CLI 选区定位，不包含网页中的原文跳转控件、覆盖汇总或完整研究包原件归档。

## 已实施契约

声明请求可选 `materialReadId`，指向 `orx materials read` 返回的 `readEventId`。客户端只提交回执 ID，不能填写服务器生成的 materialCitation。旧的无材料声明继续按原规则工作。

```json
{"text":"来源中的观察，仍须核对论证","support":"paper","source":"已登记的材料说明","location":"第 3 页第 10–15 行","materialReadId":"<readEventId>"}
```

使用 `orx research claim --file claim.json`，或在 `amend-claim` 的 replacement 中使用同一输入契约。关联须满足：

- 回执属于当前项目，原件曾核验成功，正文已准备且输出确认为 written；选区非空，页/行、长度和哈希字段一致。pending、failed、零行、未知或跨项目回执均拒绝。
- 当前计划具有固定 materialIds，包含该材料包；未知旧范围或计划外材料须先修订计划。旧计划/其他会话的读取可复用，但不会据此认定当前任务已经阅读；服务器保留实际 readerSessionId、readerStudyId 和 readerPlanVersion，手工阅读相应字段为 null。
- 登记时校验封存清单的来源、相对路径、格式、原件大小和 SHA-256；原件流式哈希在写事务外计算。提交时再次核对当前计划材料集合和回执，并检查所持文件的身份/修改状态。研究结束、材料被移出当前计划、原件在准备/提交间变化时不会追加半条声明。
- 实验声明仍须关联本项目终态 Run、有效日志行、commit 与日志哈希；materialReadId 不能代替实验执行或授权。来源关联不自动证明论文/结论在语义上得到支持。

服务器保存 materialCitation：包/SRC/路径/格式、原件哈希、PDF 页、实际行范围、编号正文的长度及哈希、原回执 ID 与实际阅读者身份。它是原始来源引用，不是自由文本 location 的猜测结果。

## 审查、交付与旧数据

新材料引用计入声明和审查 digest，登记时使当前交付批准失效。已有审稿/引用审计任务的旧摘要不能继续交付；research status 增量报告过期任务和重新审查要求，沿用现有界面提示。方案模式仍遵循其既有角色配置；若进行了声明撤回/替代，则继续遵守上一批要求的双重独立审查。

交付范围重新校验有效声明的规范引用与原回执、当前固定材料集合，并将引用元数据纳入范围 hash；已撤回的声明仍保留原来源供审计，但不参与当前交付。**本批交付不打包原件，也不在交付写锁内重新哈希所有材料**；登记和 locate 会核验当前原件，完整研究包原件快照及事务外的交付源文件校验仍待后续建设。不能将历史回执理解为当前磁盘原件始终未变的证明。

所有新字段对无引用数据省略，旧声明序列化、审查及审批哈希保持兼容。首次引用时登记 materialCitationRevision，数据库触发器拒绝旧写入器丢弃来源信息、减少引用计数或丢弃版本标记后写回；数据库管理员仍能直接更改数据库。使用本功能须同步更新后端与执行端 CLI；含引用研究不能降级到旧版继续写入。

## CLI 定位

```sh
orx materials locate <readEventId>
# Agent 会话外：
orx materials --project <project-id> locate <readEventId>
```

定位限定当前项目，按原回执的页、offset 和实际 lineCount 重读同一来源，重新核验原件 SHA-256、路径、格式及编号正文哈希/字节数。PDF/Notebook 的行号属于当次提取视图；解析器布局变化，即使原件未变，也会拒绝返回冒充原选区的正文。

成功返回 locatedReadEventId 指向原引用，另生成新的 readEventId 记录本次调用者的实际读取和输出状态，不改写原回执。失败明确报告原因；原件变化或提取结果不匹配的已登记来源产生失败回执，没有成功选区。无法接受的原回执在重读前拒绝。
