- 共用 `surface_card` 的 V2 调用一并 await，避免将已呈现标记置于未执行的 future 之后。V2 的 projection flush 和聊天最终强制 flush 仍保持原路径。
- 未调整池上限、连接生命周期、SQLite 超时或迁移规则。当前测量尚不足以证明全局连接缓存或额外写入串行化能带来净收益。

## 共享 SQLite 测量

命令：`cargo test --locked shared_sqlite_contention_benchmark -- --ignored --nocapture`。本地 macOS、debug 测试、单线程 Tokio；每个案例初始化 16 个独立会话，共享同一个 SQLite，助手正文各 64 KiB，真实打开 Store 并落盘；每次打开额外注入 20 ms 同步等待。无真实模型和业务数据，每个案例结束核对所有消息正文长度和父节点。

| 轮次 | 同步批次总耗时 | 异步批次总耗时 | 同步心跳迟到 p95 | 异步心跳迟到 p95 | 写入错误（同步/异步） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0 | 534.203 ms | 78.849 ms | 504.233 ms | 6.299 ms | 0/0 |
| 1 | 523.251 ms | 88.685 ms | 493.274 ms | 3.794 ms | 0/0 |
| 2 | 515.229 ms | 91.057 ms | 485.260 ms | 2.102 ms | 0/0 |

异步各轮同时打开 Store 的峰值均为 8。异步存储任务排队 p95 为 42.672–58.513 ms，打开 Store（包含注入等待）p95 为 39.819–53.570 ms，打开后到 flush 返回的 p95 为 7.225–9.493 ms。排队从单个任务调用 flush 前开始计时，包含快照准备、执行池等待和后台调度；不是纯 semaphore 等待。打开后阶段包含序列化、事务写入和返回调度；没有将 SQLite 锁等待单独剥离，不把这些阶段冒充纯 SQL 指标。

三个案例共 48 次异步写入全部成功（对照同步 48 次亦成功）。5 ms 心跳按固定截止点统计，阻塞时错过的截止点也计入。每个案例只有 16 个完成样本，p95/p99 接近最大值；三轮是可复现的合成基线，不是稳定的生产分位数或长期错误率保证。初始化、校验和清理不计入批次耗时，但仍计入整个测试进程的资源统计。

观测表明共享数据库下有界异步路径仍能保持调度响应；打开 Store 的额外耗时值得后续继续拆分测量。没有据此认定 SQLite 全局写锁已成为唯一瓶颈，也不以扩大线程池掩盖等待。

## 正确性验证

- 真实 SQLite `BEGIN IMMEDIATE` 持锁期间，异步心跳可以释放锁，等待中的强制 flush 随后成功；若直接在唯一异步线程同步等待，将无法及时运行释放分支。
- 普通节流尚未到期时，强制准备进度仍立即落盘。
- 两个共享数据库会话同时写入，正文和分支分别保留，已解决审批卡的 resolved/approved 回执不退回。
- 沿用第二、三批的取消后迟到写保护、失败重试、最终消息顺序与执行池 permit 回归。

最终验证通过：`cargo fmt --all --check`、`cargo clippy --locked --all-targets -- -D warnings`、`git diff --check`；完整 `cargo test --locked` 退出码为 0，1205 项单元测试、18 项集成测试通过，7 项专用测试默认忽略；共享 SQLite 基准另行显式执行通过。最初针对性编译指出 V2 共用卡片调用缺少 await，已补齐，最终 Clippy 和完整测试均针对补齐后的源码。

另以 `/usr/bin/time -l` 直接运行同一测试可执行文件的共享数据库基准，成功记录整个进程 10.89 s wall、5.72 s user、0.65 s sys，最大 RSS 44,875,776 字节（约 42.8 MiB）。这包含六个案例、夹具初始化、校验和清理，未将同步/异步 CPU 或内存分别归因，不能声称服务 RSS 或 CPU 已按此数值优化。该次批次测量也全部成功，原始数据保留，不与上表不同运行的分位数合并。

日志在忽略目录 `.mobilesci-run/backport-v0.2.20/acceptance/performance-shared-*.log`。上表取自 `performance-shared-benchmark.log`；最终回归、Clippy、进程资源分别为 `performance-shared-full-tests.log`、`performance-shared-clippy.log`、`performance-shared-resources-unrestricted.log`。首次资源命令中测试成功，但 time 因沙箱禁止读取 kern.clockrate 退出 1，不能当作完整统计；获准后重跑命令退出 0。源码及日志哈希见 `performance-shared-evidence.json`。
