# 材料阅读器第一阶段

本阶段解决上传文件夹后无法直观浏览原件的问题，沿用已封存材料包、相对路径、来源编号和 SHA-256，不另建材料存储。固定入口位于右侧“工作区 → 研究材料”，与产物、实验并列；消息中的“浏览研究材料”是定位到相应导入批次的快捷入口。

## 已实现

- 右侧“研究材料”标签页提供文件夹层级、路径搜索、格式筛选、来源与导入版本信息、下载原件。根据面板自身宽度并排显示或切换目录与正文，不遮挡会话。标签页随会话工作区保存和恢复。“当前工作树 → 文件”继续展示代码工作树。
- PDF 和图片复用现有媒体阅读器；文本按 200 行分页；较短 Markdown 支持阅读视图和原文切换。Markdown 文件链接只定位本次材料包内的文件，内嵌图片只解析已登记的包内图片。
- 文本预览上限为 1 MiB，PDF 和图片沿用单文件 32 MiB 上限。较长 Markdown 使用分页原文。CSV 以文本呈现；Notebook、XLSX 等格式提示下载，不宣称已提供专用阅读器。扫描 PDF 不在本阶段执行 OCR。
- `GET /api/materials/{id}/{source}/preview` 校验项目存在、包已封存、来源属于本包、原件尺寸及 hash，返回已校验的同一份字节。文本始终作为 `text/plain` 返回，响应包含 `nosniff`、`no-store` 和限制性 CSP。
- 客户端限制读取容量并再次核对尺寸及 hash。关闭面板、切换文件或工作区会中止请求并释放对象 URL。公开案例沿用快照原件下载资产，不访问浏览者的私有执行器。

## 阅读语义与后续顺序

浏览不会写入 AI 阅读记录；清单中的“可读取／需视觉读取”等仅表示解析能力。来源和 hash 固定到本次导入版本，同名文件不合并为同一来源。

1. 下一阶段实现选区引用到对话，固定材料包、来源、hash、文本行号或 PDF 页码，并提供回跳定位。
2. 再记录 Agent 实际读取范围与失败原因，区分读取、抽取、引用三个事实；目录存在和上传成功不能算作已阅读。
3. 最后连接结论及产物引用，补充专用表格／Notebook 阅读器、大文本分段传输和扫描件处理。

## 验证边界

新增 Rust 回归覆盖封存状态、项目及来源范围、类型与安全响应头、原件变化、文本边界和异常增长文件；前端回归覆盖目录、中文相对链接、分页、版本校验、取消及案例资产路由。

浏览器使用本地临时合成材料验证 1440px 宽屏、820px 半屏及收起侧栏、390px 窄屏、Markdown 包内跳转、PDF 实际渲染、图片、长文本翻页、不支持格式提示与 Esc 焦点恢复。临时页面及数据未进入发行资源。此验证不代表真实账号上传验收或部署已完成，现有开发服务未重启。

本轮检查通过：Rust 格式、Clippy、普通构建、全量测试（1338 项单元测试与 18 项集成测试成功，11 项既有忽略）；前端 471 项测试、类型检查、样式检查、`pnpm build` 与 UI 体积预算；版本及启动脚本回归。已重新生成提交 `ui/dist`。本机首次全量编译因磁盘不足中断，清理仓库增量编译缓存并禁用增量编译后重跑成功；回环监听测试在允许本地端口的环境运行。

## 工作区入口调整

材料列表从当前对话活动分支的已登记材料生成，避免带入放弃分支的附件；多次上传可切换导入批次。无上传材料时明确提示从输入框上传并发送，不混用工作树目录。切换会话重置材料面板内容，消息快捷入口与固定入口共用右侧标签页。

补充回归覆盖活动分支、重复引用、无效叶节点、异常循环、材料标签页与文件标签页的独立持久化，以及后端 `materials` home pane 的序列化。浏览器以临时合成数据验证真实 WorkspaceTools、MaterialChip、MaterialWorkspace 组件的固定／紧凑入口、消息入口、批次切换和 600px／760px 面板布局；未登录真实账号，未重启已有开发服务，临时验证页面不进入发行包。

调整后通过前端全量 474 项测试、Rust 工作区状态 5 项定向测试、格式／Clippy、类型／样式检查、前端构建和 UI 体积预算。此处的 Rust 定向验证不替代上文记录的上一批全量回归，也不表示本批重新运行全部 Rust 测试。
