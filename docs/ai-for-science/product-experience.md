# 本地个人版体验与交付边界

本文说明本地个人版；服务器私人托管版是另一受支持的运行形态，其数据留在服务器私人执行环境。两者的入口、数据边界和部署配置以[统一约定](../product/runtime-and-deployment.md)为准。

## 当前主线

个人版只保留两项用户可感知的产品能力：

1. OpenResearch 本地科研工作台。
2. Deep Literature 文献理解服务。

两个产品共用一个在线账号，但不共用本地运行状态。新版 OpenResearch Web 页面、产品导航和原有设置能力全部保留。

## 首次使用体验

1. 用户安装并启动 release 版本，系统打开本地网页。
2. OpenResearch 检测电脑上已有的 Codex 等 Agent，并沿用原有引导和设置完成项目创建。
3. 未登录时先展示产品能力介绍页；用户无需创建团队空间，也无需理解或配置连接器。
4. 用户点击登录后进入统一账号页；登录成功时同步建立 Deep Literature 会话并进入产品主页。
5. 进入“深度文献”后可直接打开文库或论文精读，不再重复登录。文库与笔记留在 Deep Literature，实验项目和 Agent 配置留在本机。

## 用户界面收敛

- 产品介绍由 OpenResearch 未登录首页承载；账号门户只处理注册、登录和账号管理。登录成功后同步建立 Deep Literature 会话并进入 OpenResearch 产品主页。
- 账号门户不展示工作空间、成员、角色、执行器、托管资源和连接器向导。
- OpenResearch 本地版继续展示产品介绍、开始研究、论文发现、深度文献和能力中心等新版页面。
- OpenResearch 原生设置页保持不动，继续管理 Agent、模型授权、Git、远程主机和计算后端。
- Deep Literature 入口始终使用统一 SSO，不再根据是否为云工作空间决定登录方式。

## 技术收敛策略

本地个人版不依赖托管空间和执行器。服务器私人托管版则实际使用这些能力，由系统自动准备私人运行环境；不能因为本地版不调用而删除。历史成员和邀请方案按归档设计处理，旧数据的移除须经过独立迁移和回滚验证。

## MVP 上线门槛

- release 安装、启动、升级和卸载在目标系统上完成实机验证。
- 本地 Agent 检测失败时给出可操作提示，但不要求用户理解平台连接器。
- Deep Literature 不可用时，OpenResearch 本地项目和论文发现仍可使用。
- 统一注册、登录、退出、改密、PKCE 换码、授权码重放防护和会话撤销通过集成测试。
- 明确展示数据边界，不能暗示本地项目已同步到账号或 Deep Literature。
- 上线前补齐邮箱验证和找回密码；在此之前应将账号创建范围限制在受控测试用户。

## 后续阶段

服务器私人托管版已提供独立运行形态；后续组织 GPU 调度与团队协作另行评估。云端版本应作为独立运行形态设计，由平台预装 Agent、模型接入和算力环境，不应重新把“每个用户手工配置连接器”带回个人版主流程。团队协作也应以明确的共享项目需求为起点，而不是强制所有个人用户先进入团队空间。
