# 研究交付日志范围（2026-11-02）

本批接续 v0.2.23-mobilesci.1 后的 P1 正确性工作。旧实现把所有历史计划、尝试和声明关联的 Run 全部纳入交付日志核验，导致未引用的旧日志缺失也会阻塞当前成果。新增四项回归在旧实现上全部失败，修正后全部通过；继承和元数据保护另设回归。

## 当前交付的 Run 范围

交付 `runs` 清单取以下集合的去重并集，并保持按 Run ID 排序：

1. 最新计划中每个任务的 `run_ids`，包括经验证继承到当前计划的运行结果。
2. 研究现有声明中显式填写的全部 `run_id`。实验声明继续校验登记的日志哈希；推理或论文声明的显式 Run 引用保留原有来源契约。

旧计划独有的 Run，以及 `previous_run_ids` 中未被声明引用的旧尝试，不再读取日志或计入当前交付哈希。历史 Run 被声明重新引用时，其日志仍进入交付范围，缺失或实验日志篡改会阻止交付。当前任务的日志缺失同样失败。

`research_runs` 本身保持原有全历史集合，用于运行列表、用量统计、计划修订和研究结束保护。交付先检查全历史 Run 均已结束，再核验上述范围的日志；历史未结束运行仍阻止交付。历史 Run 元数据缺失仍明确报错，不把记录损坏当成可忽略历史。此批只减少无关日志 I/O，不减少历史元数据查询量。

## 审批兼容

不新增 schema、协议字段或隐式审批迁移。现有交付 JSON 的 `runs` 范围发生变化时，其 hash 自然变化：旧请求点击会失败，原有巡检会将旧决定标为 `superseded` 并发起新申请，由用户重新确认。旧计划、决定和原始 scope 保留。

不含被排除历史 Run 的原有交付 scope 保持相同格式；同一当前交付批准后，未引用历史日志的变化或缺失不会改变当前 hash。当前产物、声明、引用日志或 Run 来源变化继续受既有范围与审批检查约束。

## 验证与剩余范围

回归覆盖无关历史日志缺失、当前日志缺失、历史及旧尝试的显式实验引用、篡改检测、历史活动运行保护、缺失元数据、当前继承结果，以及旧审批重新确认后无关历史变更的稳定性。

这不是日志 GC，也未实现声明撤回/版本化、逐任务阅读覆盖、科学指标回读或聚合 JSON 容量重构。现有全部声明仍属于交付声明集，不会自动猜测哪些声明已过时。当前历史记录和日志不执行删除。

仅改变 Rust 交付范围和相关测试，前端及内嵌 UI 不变。本地完整 Rust 1405 项单元测试和 18 项 CLI 集成测试通过，13 项既有忽略；Clippy、Rust/Windows launcher 格式、普通构建及版本基线检查通过。日志为 `/tmp/mobilesci-delivery-scope-{before,after,full,clippy,build}.log`。
