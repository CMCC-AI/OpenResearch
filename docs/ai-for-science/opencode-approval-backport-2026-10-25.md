# OpenCode 授权与停止后交互保护（2026-10-25）

基线 `cf996b4`。本批选择性回移官方 [#752](https://github.com/alphaXiv/OpenResearch/pull/752)（`3f5bac65417a42117210df2e77bf7b7e6e0fde5b`）中的 OpenCode 授权、V2 协议及过期卡片修正。产品保持 `0.2.21-mobilesci.1`、v0.2.19 真实祖先与 partial 回移状态。

## 本批完成

- **单次授权**：V1/V2 的手动批准和自动批准都发送 `once`，拒绝仍发送 `reject`，避免一次按钮点击把后续同类请求永久批准。自动模式仍按已有策略逐请求处理 native ask，不改变显式 deny 或研究 G1–G4 审批规则。
- **V2 新旧协议兼容**：既有健康探测识别的旧接口发送 `reply`，新接口发送 `decision`；手动与自动路径共用相同发送函数。工具卡片保留 metadata 中的具体命令/路径和理由，缺失时从 resources/message 补足，复用现有 UI 展示。
- **跳过语义**：V2 `approve=false` 即取消表单，即使同时带有展示 note 或旧选项，也不会误作提交；新接口 DELETE、旧接口 POST cancel 保持兼容。本批没有新增前端跳过入口。
- **Stop 后清理**：中止原生请求、等待 turn 结束并完成最后一次消息对账后，在释放 Cancelling 前关闭该助手消息中的未回答 native 卡片。递归处理嵌套卡片，保留已答选项、批准记录和 note，也保留无 native ID 的后续计划卡。单消息读取/写入在共享 8 并发后台池中执行，不为 Stop 新增全会话扫描。
- **防止旧卡片误答新 turn**：OpenCode 卡片的 UI part ID 加入所属助手消息 ID，原生请求 ID 仍保存在 nativeId；回复前核对消息是否属于当前 Active turn。已结束或另一 turn 的卡片只做无答案关闭，不调用原生回复，也不改变当前 Plan。旧格式存储仍可读取；没有变更对外答复字段或数据库 schema。

这是一批范围受控的正确性修复：没有新建队列/状态表，没有统一重写交互界面，没有引入其他 harness 的功能改造。shared Stop 清理遵守既有 native-only 语义，不清理非原生的后续审批。
