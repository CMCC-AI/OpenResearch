下一阶段在 `feat/run-input-contracts` 推进[身份保护基础](run-input-contracts-2026-11-07.md)，当前为未合入的在制代码；CLI/HTTP、G2/G3、投递和消费门禁仍须后续实现，不改变上段产品状态。

## 当前依据与缺口

- `src/compute.rs` 的 `SourceSnapshot::create` 已按 Git commit 生成内容寻址代码 tar/可选 Ray ZIP，并记录摘要、字节数与路径；`snapshot_script` 将该包解入 Run 独立 repo。不能重新发明一套代码快照，也不能把代码归档当作外部数据输入快照。
- `compute::submit` 先核查研究契约、预检与源快照，再调用 `reserve_run` 固定 starting Run，最后调用 backend.submit；提交锁及 immediate 事务内复核既有 G2/G3 契约。输入身份必须在这一闭环中绑定，不能在批准后临时选择“最新文件”。
- `src/jobs/mod.rs` 的 BackendDescriptor 是固定字段列表，parse→to_json 会丢弃未知字段。新增输入描述符必须同时检查全部构造、监控/取消/恢复写回及旧写入器，单纯加一个可选字段不够。
- `src/scientific_metrics.rs` 的 Report.data 为显式 none 或 Run 产物内 files，记录的是生产者声明及检查时观察；当前报告不证明数据在启动前已固定，不能追认成运行时事实。
- `src/local/research.rs` 的 run_contract/run_options 固定实际命令与批准范围；输入变更必须改变相应契约及审批摘要，保留旧无输入契约字节。

## 必须分别表达的事实

| 事实 | 可以据此说明什么 | 不能推出什么 |
| --- | --- | --- |
| 已登记 | 来源、原件哈希及归属可查询 | 已冻结或被执行使用 |
| 已冻结 | 声明输入的副本在指定时点可按摘要重建，清单不可变 | 当前/未来进程一定读取 |
| 已投递/可用 | 指定执行器收到指定字节并通过接收校验 | 程序实际打开、理解或科学结果依赖它 |
| 已观察到读取 | 有明确能力及范围的运行端观测事件关联进程、路径和身份 | 未观测到的输入不存在，或任意程序具备完整访问追踪 |
| 可重跑封存 | 代码/数据原件、命令和有界的环境身份已齐备 | 结果科学正确或数值完全可复现 |

输入冻结与实际消费追踪是同一最终方向的不同门禁，不能以更容易测试的投递记录替代消费证明。未知、失败和不支持的能力须明确保留。

## 实施顺序与不变量

### 1. 不可变输入集合与容量保留

以显式指定的登记材料/Run 产物为来源，路径限于原归属项目及已验证根；保留相对路径、source ID、原 SHA、大小、清单版本、总摘要和创建者版本。禁止目录链接逃逸、重复/大小写冲突、特殊文件及归档逃逸；整批超限拒绝，不省略文件。副本准备、完整哈希和复制在写事务外进行，登记时短事务复核归属、身份和容量保留；失败不留下可引用的部分集合。

共享既有可核验文件和内容寻址原语。总配额准入须按并发保留量计数，区分逻辑引用与去重后的实际占用；不能用单包上限代替总配额，也不能因超额自动删除历史输入。暂存/中断对象只有在明确没有 Run、声明、审批和在途保留引用时，才可能进入既有显式预览回收流程。

### 2. 契约、持久 Run 与全部后端

在准备运行及实际 submit 的同一来源身份中绑定集合 ID、清单摘要和冻结代码身份；变更输入需重新准备并获得既有批准。无输入旧运行不补造新字段或重算旧审批哈希。新身份启用后禁止旧二进制通过 upsert/set_backend_json/监控写回丢失它，提供明确兼容错误和升级路径。

后端能力逐个验收：local/tinker、SSH/Slurm、Ray、Kubernetes、HF/Modal、managed OpenResearch。可以分批实现，但全后端闭环仍是后续范围，不能宣称首个本地试点完成整个方向。未实现的路径在投递和收费/启动前明确拒绝，不能静默改用工作树或在线数据。恢复/重启只取固定集合，不回退“最新材料”。涉及伴随账号服务的 API 时先核对对应实现，未经范围授权不编辑伴随仓库。

### 3. 执行端事实与消费能力

执行端先校验清单和全部文件字节，再按后端实际能力提供固定路径及约定的只读方式；普通文件只读权限不等同于对同 UID 恶意进程的隔离。记录投递、校验失败、启动和结束的不同事实。事件需绑定 Run、尝试、执行器/进程身份和固定输入摘要，不能让指标生产者自行声明一段文本就晋升为可信消费记录。

消费追踪另列能力契约与威胁模型：受支持平台实际观察到的打开/读取范围可以记录；不支持、追踪失效、网络/动态生成/未声明输入必须明确未知。仅暴露环境变量、入口脚本或合成程序读取测试只能验收投递，不足以支持任意程序实际消费的全称结论。此项未闭合前，UI、报告和交付仍区分冻结/可用与已观察读取。

### 4. 指标、审查和完整封存

新观测可引用当次 Run 固定集合及执行事实，服务端校验并把来源纳入新声明/审批/交付摘要；旧 Report、登记原始字节和已批准 ZIP 保持不可变。数据原件和已有代码 tar 应封存实际字节而非只存路径/摘要；环境记录实际可核验的镜像 digest、依赖锁及工具版本，不封存凭据。跨平台环境未知不得填成“完整复现环境”。总包预算、受保护历史和失败回滚继续适用。

## 必须具备的验收证据

- 在隔离原生进程中冻结后改变原件，实际执行读取副本并核对身份；该测试只证明这个受控程序的读取，不推广至所有用户命令。
- 并发冻结与容量准入、重复引用去重、复制中断、磁盘不足、链接/特殊文件/超限、同大小替换、原件/集合丢失均失败明确，无部分可引用登记。
- 输入变更使旧 G2/G3 无法启动；重复/恢复提交绑定同集合；旧后端描述符写回不能抹掉新字段；旧无输入数据摘要保持兼容。
- 每个支持后端具备实际传输/接收/恢复证明；失败和不支持路径不启动任务、不消费远端额度。普通单元或静态 UI 夹具不能替代后端验收。
- 消费追踪能力在真实受支持执行端验证，并包含未声明输入、跟踪失效、派生进程及断线反例；没有该证据就保持未知。
- 指标引用、重做审查、ZIP 原件/摘要、历史保护和容量回收相互一致，最终冻结候选通过自己的完整 CI；源码发行和生产部署仍分开验收。

## 优先级

P1 先收敛集合、容量保留及契约/旧写入器设计，再完成执行后端适配和事实追踪，最后接指标与封存；P2 再做曲线和同单位/划分的跨 Run 对照。本方案尚不选择具体总配额数值，不以任意默认限额阻断既有用户；配置权限、逻辑/实际字节口径及并发预留必须先确定并验收。

## 下一批源码切点

以下为阶段一合入后的源码审阅结果，仍是实施清单，不计作契约或执行能力已完成。

1. `src/main.rs` 的 ExpRunArgs 与 `src/commands/up.rs` 的 CreateRunReq 双向传递显式集合。无输入旧请求保持原有语义；旧服务不能静默丢弃输入后继续运行。
2. `src/local/research.rs` 的 run_contract/run_options 将项目归属、frozen 状态和固定摘要纳入显式输入契约；`research_check_run` 与 `compute::reserve_run` 的短事务复核同一身份。完整副本哈希继续留在写事务外，无输入旧审批字节不变。
3. `src/store.rs` 的 upsert_run、set_backend_json 当前整体写回描述符；需数据库层约束，防止旧二进制、恢复写回或 commit_sha 变化抹去新身份。描述符可选字段本身不能提供这层保护，同时须保留旧无输入 Run 及取消/查询能力。
4. `compute.rs` 初始描述符及 `src/local/{localrun,ssh,slurm,ray,k8s,hf,modal,openresearch}.rs` 分别重建描述符，localrun 还共用 local/tinker 模式。需逐个携带身份并明确能力，不能只改主 submit。
5. `compute::{record_submission_handle,recover_submission_handle}` 另存 JSON，supervise 可由文件恢复整个描述符。必须验证 Run、输入及代码身份一致；数据库因身份保护拒绝时，不能误当普通数据库不可用而降级写入不安全恢复文件。
6. 本地受控进程先提供实际投递及冻结后原件变化的读取验收；未支持后端必须在创建/收费前拒绝显式输入。不把拒绝分支计作远端投递，不把受控程序读取推广成任意程序的完整消费证明。
